# route-planning · 업무 흐름

> 근거: `domain-entities.md` (R-1~R-7) · `business-rules.md` (RBR-1~RBR-46) · `components.md` (C-2 · C-7)
> 계산은 **C-2 동선 계산** 하나다. **C-7 지도 창구**는 외부와 닿는 자리다.

## C-2 동선 계산 — 이 단위의 핵심 계산

### 받는 것과 주는 것

```
받는 것 :  RoutePlanningInput          (schedule-core 의 경계 1)
             · 펼쳐진 일정 목록
             · 하루 설정 (출발지 · 마지막 도착지)
             · 기본 이동 수단 · 캐시 유지 시간
        +  이동 시간을 물어볼 수단        (C-7 을 넘겨받는다)
        +  지금 시각                    (밖에서 주입한다 — RBR-8)
        +  앞날 하루 시작 시각            (설정)

주는 것 :  R-5 동선 결과
        또는  R-6 도착 불가 경고 목록      (RBR-17 — 이 경우 순서를 주지 않는다)
```

### 왜 이동 시간을 받아 쓰나

C-2 는 **외부를 직접 부르지 않는다.** 이동 시간을 물어볼 수단을 인자로 받는다.
그래서 대역을 넣으면 외부 서비스 없이 테스트된다 (NFR-3.1 · S-7 수락 기준).
지금 시각도 주입받는다. RBR-8 이 지금 시각에 매달려 있으므로 그렇지 않으면 테스트가 시간에 흔들린다.

### 어떤 순서로 하나

```
1. 계산할 일정을 고른다
   1-1. 완료 표시된 일정을 뺀다                                    RBR-7
   1-2. 좌표가 없는 일정을 뺀다. 빠진 목록(R-7)에 담는다             RBR-21 · RBR-22
   1-3. 하루 출발지에 좌표가 없으면 여기서 멈춘다                    RBR-23
   1-4. 남은 일정이 없으면 그 사실을 알리고 멈춘다                   RBR-26

2. 순서를 정한다
   2-1. 고정형을 도착 시각이 이른 것부터 늘어놓는다                  RBR-1
   2-2. 손으로 고정한 자리가 있으면 그 자리를 잡아 둔다               RBR-6 · RBR-42
   2-3. 유연형을 고정형 **뒤에** 가까운 곳부터 이어 붙인다            RBR-3 · RBR-5
          지금 있는 곳에서 이동 시간이 가장 짧은 곳을 다음으로 고른다
          (마지막 고정형의 장소에서 시작. 고정형이 없으면 하루 출발지에서)

3. 구간마다 이동 시간을 받는다
   3-1. 앞 지점 → 다음 지점 · 그 일정의 이동 수단으로 조회            RBR-27
   3-2. 같은 구간은 한 번만 조회한다                                RBR-46

4. 시각을 계산한다
   4-1. 하루 첫 출발 시각을 정한다                                  RBR-8
          오늘이면 지금 시각 · 앞날이면 설정의 하루 시작 시각
   4-2. 구간마다 앞에서부터 이어 계산한다
          유연형 도착 시각 = 앞이 끝난 시각 + 이동 시간              RBR-10
          앞이 끝난 시각    = 도착 시각 + 머무는 시간                RBR-11
   4-3. 고정형은 정해진 도착 시각을 그대로 쓴다                      RBR-2
          출발 시각 = 정해진 도착 시각 − 이동 시간                   RBR-12
          일찍 닿으면 기다린다. 기다린 시간은 이동 시간에 넣지 않는다  RBR-13
   4-4. 첫 일정이 고정형이고 4-3 의 출발 시각이 4-1 보다 이르면
        4-1 을 쓰지 않는다                                        RBR-9

5. 도착 불가를 본다
   5-1. 고정형마다 — 앞이 끝나고 이동해서 닿는 시각 > 정해진 도착 시각 ?  RBR-16
   5-2. 하나라도 있으면 순서를 주지 않고 경고 목록만 준다               RBR-17
          모두 모아 준다. 첫 번째만 주지 않는다                       RBR-19

6. 결과를 낸다
   6-1. 총 이동 시간 = 구간 이동 시간의 합 (기다린 시간 제외)          RBR-13
   6-2. 구간 중 하나라도 `stale` 이면 낡은 값이 있다고 표시            RBR-31 · RBR-34
   6-3. 빠진 일정 목록을 함께 담는다                                 RBR-22
   6-4. 순서를 어떻게 정했는지 담는다 (`가까운 곳부터 이어 붙임`)       RBR-5
```

### Q1-B 가 계산을 어떻게 단순하게 만들었나

유연형을 고정형 사이에 끼우지 않으므로 **순서가 두 덩어리로 나뉜다.**

```
[ 고정형 — 시각 순서대로 고정 ]  →  [ 유연형 — 가까운 곳부터 ]
```

앞 덩어리는 정렬만 하면 끝이고, 뒷 덩어리만 순서를 궁리하면 된다.
Q1-A 를 골랐다면 고정형 사이의 빈 시간마다 유연형을 넣어보는 계산이 필요했다.

### 경계 상황 — 완료 기준이 되는 것들

| 상황 | 무엇이 나와야 하나 | 규칙 |
|---|---|---|
| 일정이 없다 | 계산할 것이 없다고 알린다. 오류가 아니다 | RBR-26 |
| 일정이 하나다 | 출발지 → 그 일정 (+ 마지막 도착지) 구간이 나온다 | — |
| 고정형만 있다 | 시각 순서 그대로. 유연형 배치 계산을 하지 않는다 | RBR-1 |
| 유연형만 있다 | 가까운 곳부터 이어 붙인 순서 | RBR-4, RBR-5 |
| 고정형과 유연형이 섞여 있다 | 고정형이 먼저, 유연형이 뒤 | RBR-3 |
| 고정형 사이에 시간이 많이 남는다 | 유연형을 그 사이에 넣지 않는다 | RBR-3 (Q1-B) |
| 고정형에 일찍 닿는다 | 기다린다. 기다린 시간이 총 이동 시간에 안 들어간다 | RBR-13 |
| 고정형 두 개를 이을 수 없다 | 순서 대신 도착 불가 경고 | RBR-16, RBR-17 |
| 도착 불가가 두 곳에서 생긴다 | 둘 다 알린다 | RBR-19 |
| 좌표 없는 일정이 있다 | 빼고 계산하고 빠진 것을 알린다 | RBR-21, RBR-22 |
| 좌표 없는 일정이 고정형이다 | 빼되 더 눈에 띄게 알린다 | RBR-25 |
| 좌표를 뺀 뒤 남은 일정이 없다 | 계산할 것이 없다고 알린다 | RBR-26 |
| 하루 출발지에 좌표가 없다 | 계산하지 않는다 | RBR-23 |
| 마지막 도착지가 비어 있다 | 마지막 일정에서 끝난다 | RBR-24, BR-20 |
| 손으로 고정한 자리가 있다 | 그 자리를 지키고 나머지만 계산 | RBR-6, RBR-42 |
| 손으로 잡은 순서가 늦게 된다 | 경고를 주되 막지 않는다 | RBR-43 |
| 오늘을 본다 | 첫 출발 시각이 지금 시각 | RBR-8 |
| 앞날을 본다 | 첫 출발 시각이 설정의 하루 시작 시각 | RBR-8 |
| 지난 날짜를 본다 | 지금 시각을 쓰지 않는다 | RBR-15 |
| 자정을 넘긴다 | 시각이 어긋나지 않는다 | RBR-14 |
| 외부가 실패하고 옛 값이 있다 | 옛 값을 쓰고 `stale` 로 표시 | RBR-31 |
| 외부가 실패하고 옛 값도 없다 | 그 구간을 계산할 수 없다고 알린다 | RBR-32 |

## C-7 지도 창구 — 외부와 닿는 자리

이 앱에서 외부와 닿는 곳은 C-7 과 C-8 두 군데뿐이다 (NFR-5.1). C-7 은 두 가지를 한다.

### 주소↔좌표 (RBR-35~RBR-40)

```
받는 것 :  사용자가 친 글자
주는 것 :  R-1 좌표 후보 목록  (0개 · 1개 · 여러 개)

   0개  →  좌표를 비워 둔다. 그 일정은 동선에서 빠진다        RBR-38 · RBR-21
   1개  →  자동으로 확정한다                                RBR-37
  여러개 →  사용자가 고른다                                  RBR-36

확정되면  →  schedule-core 의 보관소에 좌표와 이름을 남긴다     RBR-39
```

### 이동 시간 조회 (RBR-27~RBR-34)

```
받는 것 :  출발 좌표 · 도착 좌표 · 이동 수단
주는 것 :  R-2 이동 시간 조회 결과 (이동 시간 + 세 상태 중 하나)

┌─ 캐시에 있고 유지 시간 안인가?
│     예  →  저장된 값을 준다.  상태 = cached                RBR-28
│     아니오 ↓
├─ 외부에 묻는다
│     성공  →  값을 주고 캐시에 남긴다.  상태 = fresh         RBR-27
│     실패 ↓
├─ 캐시에 옛 값이 있나?
│     예  →  옛 값을 준다.  상태 = stale  (화면에 알린다)     RBR-31 · RBR-34
│     아니오 →  이 구간을 계산할 수 없다고 알린다             RBR-32
└─
사용자가 `새로 계산` 을 누르면 캐시를 무르고 위를 다시 돈다      RBR-29
```

**`cached` 와 `stale` 을 가르는 것이 이 흐름의 핵심이다.** 앞은 정상이므로 알리지 않고,
뒤는 값이 낡았으므로 알린다 (FR-6.3).

### 캐시에서 구간을 견주는 방법 (RBR-30)

```
같은 구간인가?  =  출발 좌표 · 도착 좌표를 정해진 소수 자릿수까지 자른 값이 같고
                  이동 수단도 같은가
```

자릿수를 설정에 둔다. 너무 촘촘하면 같은 장소인데 캐시가 안 맞고, 너무 거칠면 다른 장소를 같다고 본다.

### 비밀값 (RBR-33)

외부 접근에 쓰는 키는 소스에 넣지 않고 실행 환경에서 받는다.
**다만 Vite 는 빌드할 때 값을 결과물에 박아 넣는다.** 브라우저로 내려가는 키는 감춰지지 않는다.
이 사실을 STEP 02 에서 어떻게 다룰지 정한다 (`schedule-core/tech-stack-decisions.md` 가 짚어 둔 것).

## 경계 2 로 넘기기 — `departure-alarm`

```
C-2 의 R-5 동선 결과  ─────▶  departure-alarm
   또는 R-6 도착 불가 경고  ──▶  departure-alarm (알림을 걸지 않는다)
```

| 이 단위가 하는 것 | 이 단위가 하지 않는 것 |
|---|---|
| 구간마다 출발 시각 · 도착 시각을 계산한다 | 여유 시간을 빼지 않는다 (FR-5.3 은 `departure-alarm`) |
| 이동 시간이 최신인지 함께 넘긴다 | 알림을 걸지 않는다 |
| 도착 불가면 경고를 넘긴다 | — |

`departure-alarm` 은 이동 시간을 스스로 구하지 않는다. 여기서 받은 값만 쓴다 (`unit-of-work.md` 경계 2).
이동 시간이 바뀌면 이 단위가 결과를 다시 내고, `departure-alarm` 이 알림을 다시 잡는다 (FR-6.2).

## 경계 4 로 받기 — `meetup-midpoint`

```
meetup-midpoint  ──▶  "약속 장소가 확정됐다"  ──▶  이 단위가 동선을 다시 낸다
```

확정된 장소는 `schedule-core` 의 일정에 이미 들어가 있다 (경계 3).
이 단위는 그 일정을 새로 읽어 계산만 다시 한다. 장소를 직접 받지 않는다.

|---|---|
| 일정을 펼치기 · 보관하기 | schedule-core (C-1 · C-5) |
| 출발 시각에서 여유 시간 빼기 · 알림 걸기 | departure-alarm (C-4) |
| 중간지점 계산 · 장소 후보 조회 | meetup-midpoint (C-3 · C-8) |
