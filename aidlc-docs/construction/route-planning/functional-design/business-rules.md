# route-planning · 업무 규칙

> 근거: `requirements.md` FR-2 · FR-6 · NFR-2.1 · NFR-2.3 · `stories.md` S-7~S-10 · `domain-entities.md`
> 답: Q1-B · Q2-C · Q3-B · Q4-A · Q5-C
> 규칙 번호는 `RBR-` 로 시작한다. `schedule-core` 의 `BR-` 와 섞이지 않게 한다.
> **수치는 여기 박지 않고 설정에 둔다** (NFR-5.2).

## 1. 순서를 어떻게 정하나 (Q1-B · Q2-C)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-1 | 시간 고정형 일정은 지정된 도착 시각이 이른 것부터 늘어놓는다. 이 순서를 앱이 바꾸지 않는다 | FR-2.3, NFR-2.1 |
| RBR-2 | 시간 고정형 일정의 도착 시각을 앱이 고치지 않는다 | FR-2.3, NFR-2.1 |
| RBR-3 | **유연형 일정은 고정형 일정 사이에 끼우지 않는다.** 모든 고정형이 끝난 뒤에 놓는다 | Q1-B |
| RBR-4 | 고정형이 하나도 없으면 유연형만으로 순서를 정한다 | Q1-B |
| RBR-5 | 유연형끼리의 순서는 **가까운 곳부터 이어 붙여** 정한다. 지금 있는 곳에서 이동 시간이 가장 짧은 곳을 다음으로 고르고, 그것을 되풀이한다 | Q2-C |
| RBR-6 | 사용자가 손으로 고정한 자리는 그 자리에 둔다. 나머지만 RBR-5 로 정한다 | FR-2.6, S-10 |
| RBR-7 | 완료 표시된 일정은 순서에서 뺀다 | FR-1.6, BR-15 |

### RBR-5 가 FR-2.2 와 어긋나는 대목

`requirements.md` FR-2.2 는 최적화의 목표를 **총 이동 시간 최소화**로 정했다.
Q2-C 를 골랐으므로 가까운 곳부터 이어 붙이는 방식을 쓰는데, 이 방식은 **가장 짧은 순서를 보장하지 않는다.**

| 무엇 | 어떻게 다루나 |
|---|---|
| 목표는 그대로 총 이동 시간 최소화다 | 매 단계에서 이동 시간이 가장 짧은 곳을 고른다 |
| 그 결과가 가장 짧다고 보장하지 않는다 | 화면에 순서를 어떻게 정했는지 밝힌다 (R-5 `어떻게 순서를 정했는지`) |
| 사용자가 더 나은 순서를 알면 | 손으로 옮겨 고정할 수 있다 (RBR-6 · S-10) |

Q1-B 를 함께 골랐으므로 유연형이 고정형 뒤로 몰린다. 그래서 견줄 조합 자체가 크게 줄고,
가까운 곳부터 이어 붙이는 방식으로도 결과가 크게 나빠지지 않는다.

## 2. 시각을 어떻게 계산하나 (Q3-B)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-8 | 하루의 첫 출발 시각은 — 오늘이면 **지금 시각**, 앞날이면 설정의 **앞날 하루 시작 시각** | Q3-B |
| RBR-9 | 첫 일정이 고정형이면 그 도착 시각에서 이동 시간을 빼서 출발 시각을 구한다. 그 값이 RBR-8 보다 이르면 RBR-8 을 쓰지 않는다 | FR-2.4 |
| RBR-10 | 유연형 일정의 도착 시각은 계산한다 — 앞 구간이 끝난 시각 + 이동 시간 | FR-2.4 |
| RBR-11 | 앞 일정이 끝나는 시각은 `도착 시각 + 머무는 시간` 이다. 보관하지 않고 구한다 | BR-50 |
| RBR-12 | 고정형 일정의 출발 시각은 `정해진 도착 시각 − 이동 시간` 이다 | FR-2.4 |
| RBR-13 | 고정형 일정에 일찍 닿으면 그 자리에서 기다린다. 기다리는 시간은 이동 시간에 넣지 않는다 | FR-2.2 |
| RBR-14 | 시각은 사용자의 표준시로 다룬다. 자정을 넘어도 어긋나지 않는다 | NFR-2.3, BR-48 |
| RBR-15 | 지난 날짜를 볼 때는 지금 시각을 쓰지 않는다. 그 날짜의 첫 고정형 일정에서 거꾸로 계산하고, 고정형이 없으면 설정의 하루 시작 시각을 쓴다 | Q5-A, Q3-B |

### RBR-13 이 필요한 이유

14시 치과에 13시 40분에 닿으면 20분을 기다린다. 그 20분은 **이동한 시간이 아니다.**
총 이동 시간(FR-2.2)에 기다린 시간을 넣으면 순서를 견줄 때 엉뚱한 답이 나온다.

## 3. 도착 불가 판정 (S-9 · NFR-2.1)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-16 | 앞 일정이 끝나고 이동해서 닿는 시각이 다음 고정형 일정의 정해진 도착 시각보다 늦으면 **도착 불가**다 | FR-2.5 |
| RBR-17 | 도착 불가가 하나라도 있으면 순서를 주지 않는다. 경고만 준다 | FR-2.5, NFR-2.1 |
| RBR-18 | 경고에는 어느 일정에 닿을 수 없는지 · 몇 분 모자라는지 · 앞의 어느 일정 때문인지를 담는다 | S-9 |
| RBR-19 | 여러 곳에서 도착 불가가 생기면 모두 알린다. 첫 번째만 알리지 않는다 | S-9 |
| RBR-20 | 사용자가 문제되는 일정의 시각이나 이동 수단을 고치면 다시 계산하고, 가능해지면 경고가 사라진다 | S-9 |

## 4. 좌표를 못 찾은 일정 (Q4-A)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-21 | 좌표가 없는 일정은 동선에서 빼고 나머지로 계산한다 | Q4-A |
| RBR-22 | 빠진 일정을 **반드시 화면에 알린다.** 왜 빠졌는지도 함께 | Q4-A |
| RBR-23 | 하루 출발지에 좌표가 없으면 계산하지 않는다. 첫 구간이 시작될 곳이 없다 | BR-19 |
| RBR-24 | 마지막 도착지에 좌표가 없으면 그 구간만 빼고 계산한다. 마지막 일정에서 끝난다 | BR-20, Q4-A |
| RBR-25 | 좌표가 없는 일정이 고정형이어도 뺀다. 다만 뺐다는 사실을 더 눈에 띄게 알린다 | Q4-A |
| RBR-26 | 좌표를 뺀 결과 계산할 일정이 하나도 남지 않으면, 계산 결과 대신 그 사실을 알린다 | Q4-A |

### RBR-25 를 왜 이렇게 정했나

고정형 일정이 빠지면 도착 불가 판정(RBR-16)도 함께 사라진다. 사용자가 늦을 수 있는 상황을
앱이 못 잡게 되는 것이다. 그래서 뺐다는 사실을 다른 것보다 눈에 띄게 알려야 한다.

## 5. 이동 시간 받아오기와 캐시 (Q5-C · FR-6.1 · NFR-1.3)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-27 | 이동 시간은 실시간 교통 상황이 반영된 값을 받는다 | FR-6.1 |
| RBR-28 | 같은 구간 · 같은 이동 수단은 캐시 유지 시간 안에서 저장된 값을 쓰고 외부를 부르지 않는다 | NFR-1.3, Q5-A |
| RBR-29 | 사용자가 `새로 계산` 을 누르면 캐시를 무르고 모두 다시 받는다 | Q5-C |
| RBR-30 | 캐시에서 구간을 견줄 때 좌표를 정해진 소수 자릿수까지만 본다. 자릿수는 설정에 둔다 | NFR-1.3, NFR-5.2 |
| RBR-31 | 외부가 응답하지 않으면 마지막으로 받아 둔 값을 쓰고 **최신이 아님을 표시**한다 | FR-6.3 |
| RBR-32 | 받아 둔 값도 없고 외부도 실패하면 그 구간을 계산할 수 없다. 그 사실을 알린다 | FR-6.3 |
| RBR-33 | 외부 접근에 쓰는 비밀값은 소스에 넣지 않고 실행 환경에서 받는다 | NFR-4.1 |
| RBR-34 | 캐시가 정상으로 쓰인 것(`cached`)과 실패해서 옛 값을 쓴 것(`stale`)을 가른다. 앞은 알리지 않고 뒤는 알린다 | FR-6.3 |

## 7. 손으로 순서 옮기기 (S-10 · FR-2.6)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-41 | 추천된 순서를 받아들이면 그 순서가 그날의 동선으로 저장된다 | S-10 |
| RBR-42 | 일정 하나의 자리를 손으로 옮기면 그 자리가 고정되고 나머지만 다시 계산된다 | S-10, FR-2.6 |
| RBR-43 | 손으로 잡은 순서가 고정형 일정에 늦게 되면 경고를 보여주되 저장은 막지 않는다 | S-10 |
| RBR-44 | 손으로 고정한 자리는 `schedule-core` 의 일정에 남는다 (E-2 `손으로 고정한 자리`) | E-2 |

RBR-43 은 RBR-17 과 다르다. **앱이 정한 순서는 도착 불가면 내지 않지만, 사람이 정한 순서는 막지 않는다.**
앱이 모르는 사정이 있을 수 있고, 계산이 사람의 판단을 덮어써서는 안 된다.

## 8. 성능 (NFR-1.1)

| 번호 | 규칙 | 근거 |
|---|---|---|
| RBR-45 | 일정 10개 기준으로 동선 결과가 3초 안에 나온다 | NFR-1.1 |
| RBR-46 | 같은 구간을 두 번 조회하지 않는다. 한 번 계산하는 동안 받은 값을 함께 쓴다 | NFR-1.3 |

Q1-B · Q2-C 를 고른 결과 조합 폭발이 없어져 RBR-45 를 맞추기 쉬워졌다.
가까운 곳부터 이어 붙이려면 유연형 n 개에 대해 최대 n(n−1)/2 번의 구간 조회가 필요하다. 10개면 45번이고, 캐시가 있으면 그보다 적다.
