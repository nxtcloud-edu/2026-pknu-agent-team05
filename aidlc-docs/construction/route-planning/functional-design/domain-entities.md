## R-1. 좌표 후보 (C-7 주소↔좌표)

사용자가 친 글자로 외부에서 찾은 결과다. 골라서 확정하면 `schedule-core` 의 `Place` 에 들어간다 (Q2-C).

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 이름 | 찾아낸 장소 이름. `Place.resolvedName` 이 된다 | 아니오 |
| 주소 | 사람이 읽을 주소. 후보를 구별하는 데 쓴다 | 예 |
| 좌표 | 위도 · 경도. `Place.coord` 가 된다 | 아니오 |

**후보가 하나면 자동으로 확정한다** (BR-26). 여럿이면 사용자가 고른다 (BR-25). 하나도 없으면 R-7 로 이어진다 (Q4-A).

## R-2. 이동 시간 조회 결과 (C-7 길찾기)

한 구간을 물어 받은 답이다.

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 이동 시간 | 분 | 아니오 |
| 언제 받은 값인지 | 조회 시각 | 아니오 |
| 최신인지 | 방금 받았나, 예전 값을 쓰고 있나 (FR-6.3) | 아니오 |
| 어느 이동 수단으로 | 도보 · 대중교통 · 자동차 | 아니오 |

### `최신인지` 가 필요한 이유

외부가 응답하지 않으면 마지막으로 받아 둔 값을 쓰고, **최신이 아님을 화면에 표시해야 한다** (FR-6.3).
그 표시가 화면까지 올라가려면 값과 함께 따라와야 한다.

세 가지 상태가 있다.

| 상태 | 언제 |
|---|---|
| `fresh` | 방금 외부에서 받았다 |
| `cached` | 캐시 유지 시간 안이라 저장된 값을 썼다 (Q5-A · 정상) |
| `stale` | 외부가 실패해서 유지 시간이 지난 옛 값을 쓰고 있다 (FR-6.3 · 화면에 알린다) |

`cached` 와 `stale` 을 가르는 것이 중요하다. 앞은 정상이고 뒤는 알려야 하는 상태다.

## R-3. 이동 시간 캐시 항목 (보관된다 · NFR-1.3)

| 값 | 의미 |
|---|---|
| 출발 좌표 · 도착 좌표 · 이동 수단 | 이 셋이 같으면 같은 구간이다 |
| 이동 시간 | 분 |
| 언제 받았는지 | 유지 시간이 지났는지 판정한다 |

**좌표를 소수 몇 자리까지 견줄지 정해야 한다.** 같은 장소인데 소수 끝자리가 달라 캐시가 안 맞으면 뜻이 없다.
그 자릿수는 설정에 둔다 (NFR-5.2).

## R-4. 구간

한 곳에서 다음 곳으로 가는 하나의 이동이다. 동선 결과가 이것들로 이뤄진다.

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 어디서 | 출발 지점 — 하루 출발지이거나 앞 일정의 장소 | 아니오 |
| 어디로 | 도착 지점 — 일정의 장소이거나 하루 마지막 도착지 | 아니오 |
| 어느 일정으로 가는 구간인지 | 마지막 도착지로 가는 구간이면 비어 있다 | 예 |
| 목적지 이름 | 알림 문구에 들어간다 (경계 2 · FR-5.4) | 아니오 |
| 이동 수단 | 도착하는 일정에 지정된 것 | 아니오 |
| 이동 시간 | R-2 에서 받은 값 | 아니오 |
| 값이 최신인지 | R-2 의 세 상태 | 아니오 |
| 출발 시각 | 계산된 값 | 아니오 |
| 도착 시각 | 계산된 값 | 아니오 |
| 머무는 시간 | 도착한 뒤 그곳에 있는 시간. 마지막 도착지면 0 | 아니오 |

### 도착 시각이 두 가지 뜻을 가진다

| 어떤 일정인가 | 도착 시각이 무엇인가 |
|---|---|
| 시간 고정형 | 사용자가 정한 시각. 앱이 바꾸지 않는다 (FR-2.3) |
| 유연형 | 계산된 시각. 앞 구간이 끝난 뒤 이동해서 닿는 시각 |

## R-5. 동선 결과

계산이 성공했을 때 나오는 것이다.

| 값 | 의미 |
|---|---|
| 날짜 | 어느 날의 동선인지 |
| 순서 | 확정된 일정 순서 |
| 구간들 | R-4 목록. 첫 구간은 하루 출발지에서 시작한다 |
| 총 이동 시간 | 구간의 이동 시간을 모두 더한 값 |
| 하루 출발 시각 | 첫 구간의 출발 시각 (Q3-B 로 정해진다) |
| 하루 끝 시각 | 마지막 구간이 끝나는 시각 |
| 빠진 일정 | R-7 목록. 좌표를 못 찾아 계산에서 뺀 것 (Q4-A) |
| 값이 낡은 구간이 있는지 | 구간 중 하나라도 `stale` 이면 참 (FR-6.3) |
| 어떻게 순서를 정했는지 | `가까운 곳부터 이어 붙임` (Q2-C). 화면에 밝힌다 |

## R-6. 도착 불가 경고 (S-9)

계산이 실패했을 때 순서 대신 나오는 것이다 (FR-2.5 · NFR-2.1).

| 값 | 의미 |
|---|---|
| 어느 일정에 닿을 수 없는지 | 일정 이름과 제목 |
| 몇 분 모자라는지 | 앞 일정이 끝나고 이동해서 닿는 시각 − 정해진 도착 시각 |
| 앞의 어느 일정 때문인지 | 무엇을 고쳐야 하는지 알려주기 위해 |

**경고가 있으면 순서를 주지 않는다** (NFR-2.1). 불가능한 계획을 그럴듯한 추천으로 내지 않는다.

## R-7. 빠진 일정 (Q4-A)

좌표를 못 찾아 동선에서 뺀 일정이다.

| 값 | 의미 |
|---|---|
| 어느 일정인지 | 이름과 제목 |
| 왜 빠졌는지 | `좌표를 못 찾음` 또는 `주소가 비어 있음` |

빠졌다는 사실을 **반드시 화면에 알린다.** 조용히 빼면 사용자가 왜 그 일정이 동선에 없는지 알 수 없다.

## 설정에 더해지는 값

`schedule-core` 의 E-7 설정에 이 단위가 쓰는 값을 더한다.
`components.md` C-6 에 이미 예정돼 있던 것과, Q3-B · Q5-C 가 새로 만든 것이 있다.

| 값 | 어디서 왔나 | 누가 바꾸나 |
|---|---|---|
| 이동 시간 캐시 유지 시간 (분) | C-6 에 예정돼 있었다 | 앱 |
| **앞날의 하루 시작 시각** | **Q3-B 가 새로 만들었다** | 사용자 |
| 캐시에서 좌표를 견줄 소수 자릿수 | 이 단위가 새로 만들었다 | 앱 |

`앞날의 하루 시작 시각` 은 `schedule-core` 의 설정에 칸을 더하는 것이다.
기존 동작을 깨지 않는 추가이므로 그 자리에서 고친다 (`unit-of-work.md` Q4-C 기준). 아래 `앞 단위를 고친 것` 을 보라.

## 경계 2 로 넘기는 것 — `departure-alarm`

`unit-of-work.md` 경계 2 가 요구하는 값이 위에 다 있는지 확인한다.

| 경계 2 가 요구하는 것 | 어디에 있나 |
|---|---|
| 확정된 순서 | R-5 순서 |
| 어느 일정으로 가는 구간인지 | R-4 `어느 일정으로 가는 구간인지` |
| 목적지가 어디인지 | R-4 목적지 이름 |
| 출발 시각 · 도착 시각 · 이동 시간 · 이동 수단 | R-4 |
| 이동 시간이 최신인지 | R-4 `값이 최신인지` (R-2 의 세 상태) |
| 또는 도착 불가 경고 | R-6 — 이 경우 `departure-alarm` 은 알림을 걸지 않는다 |

## 앞 단위를 고친 것 (Q4-C 기준 · 그 자리에서 고침)

Q4-A 를 고른 결과 `schedule-core` 두 곳을 고쳐야 한다. 무엇을 왜 고치는지 남긴다.

| 무엇 | 왜 | 어느 경우에 해당하나 |
|---|---|---|
| `domain/handoff.ts` 의 `checkRouteReadiness` — `missing-coords` 를 계산 막힘으로 판정하던 것을 푼다 | Q4-A 로 "좌표 없는 일정은 빼고 나머지로 계산한다" 가 정해졌다. 좌표 정책은 이 단위에서 정한다고 `schedule-core` BR-21 에 적혀 있다 | 설계에 예정된 자리를 채우는 것 |
| `domain/settings/` 에 `앞날의 하루 시작 시각` 을 더한다 | Q3-B 가 요구한다. 기존 값을 건드리지 않고 칸을 더한다 | 기존 동작을 깨지 않는 추가 |

둘 다 `unit-of-work.md` 의 `그 자리에서 고친다` 에 해당한다. 되돌아가지 않는다.
`checkRouteReadiness` 는 `schedule-core` 의 완료 기준(경계 상황 14가지)에 들어 있지 않아 그 기준이 무너지지도 않는다.
