## V-3 동선 결과

`DayView` 의 점선 자리를 채운다. 하루 보기 안에 그대로 들어가고 패널로 열리지 않는다 (Q1-C).

### 계산이 성공했을 때

```
동선 추천                                      [새로 계산]
가까운 곳부터 이어 붙인 순서입니다              ← RBR-5 를 밝힌다
총 이동 시간 1시간 20분 · 09:30 나가서 21:00 끝

  09:30  집
    │    ↓ 25분 · 대중교통
  09:55  장 보기            30분 머묾
    │    ↓ 15분 · 도보
  13:40  치과 진료  ⏰       40분 머묾   ← 고정형은 표시가 붙는다
    │      3시간 15분 기다림              ← RBR-13 · 이동 시간에 안 들어간다
    │    ↓ 40분 · 대중교통
  19:00  민수와 저녁  ⏰      90분 머묾
    │    ↓ 20분 · 대중교통
  21:00  집

  ⋮ 순서를 옮기려면 일정을 끌어 놓으세요
```

| 무엇을 보여주나 | 근거 |
|---|---|
| 총 이동 시간 · 하루 출발 시각 · 하루 끝 시각 | R-5 |
| 구간마다 이동 시간 · 이동 수단 | FR-2.4 |
| 일정마다 도착 시각 · 머무는 시간 | FR-2.4 |
| 고정형 표시 | RBR-2 — 앱이 이 시각을 바꾸지 않았음을 보인다 |
| 기다리는 시간 | RBR-13 — 이동 시간과 다르다는 것을 드러낸다 |
| 순서를 어떻게 정했는지 | RBR-5 — 가장 짧은 순서를 보장하지 않으므로 밝힌다 |

### 기다리는 시간을 왜 보여주나

RBR-13 은 기다린 시간을 총 이동 시간에 넣지 않는다. 그런데 화면에서 감추면
"09:55 에 30분 머무는데 왜 13:40 에 도착하나" 가 설명되지 않는다. 시간이 어디로 갔는지 보여야 한다.

3시간 넘게 기다리는 결과가 나오면 Q1-B 때문이다. 유연형을 고정형 사이에 끼우지 않기로 했으니
빈 시간이 그대로 남는다. 사용자가 이것을 보고 손으로 순서를 옮길 수 있다 (RBR-42).

### 도착 불가일 때 (RBR-17)

순서를 보여주지 않는다. 경고만 보여준다.

```
⚠ 제때 도착할 수 없는 일정이 있습니다

  치과 진료 14:00
    장 보기가 13:50 에 끝나고 25분 이동하면 14:15 에 닿습니다.
    15분 모자랍니다.

  민수와 저녁 19:00
    치과 진료가 18:40 에 끝나고 40분 이동하면 19:20 에 닿습니다.
    20분 모자랍니다.

  도착 시각이나 이동 수단, 머무는 시간을 고쳐보세요.
```

| 규칙 | 화면에서 |
|---|---|
| RBR-17 순서를 주지 않는다 | 동선 목록을 아예 그리지 않는다 |
| RBR-18 몇 분 모자라는지 | 경고마다 표시 |
| RBR-18 앞의 어느 일정 때문인지 | 원인 일정을 함께 |
| RBR-19 여러 곳이면 모두 | 목록으로 |
| RBR-20 고치면 사라진다 | 다시 계산하면 경고가 없어진다 |

### 빠진 일정이 있을 때 (RBR-22)

동선과 **함께** 보여준다. 계산은 됐지만 일부가 빠졌다는 것을 알려야 한다.

```
동선에서 빠진 일정 2개
  · 새로 생긴 카페 — 주소를 찾지 못했습니다
  · 민수와 저녁 ⏰ — 장소가 아직 정해지지 않았습니다   ← 고정형이라 더 눈에 띈다
  주소를 고치면 동선에 들어갑니다.
```

고정형이 빠지면 다르게 보여야 한다 (RBR-25). 고정형이 빠지면 도착 불가 판정도 함께 사라져서,
늦을 수 있는 상황을 앱이 못 잡게 된다.

### 값이 낡았을 때 (RBR-31 · RBR-34)

```
⚠ 이동 시간이 최신이 아닙니다
  길찾기 서비스에 닿지 못해 2시간 전에 받은 값을 쓰고 있습니다.
  [다시 받아보기]
```

`cached` 상태는 알리지 않는다. 정상이다. `stale` 만 알린다 (RBR-34).

### 계산할 수 없을 때

| 상황 | 무엇을 보여주나 | 근거 |
|---|---|---|
| 하루 출발지에 좌표가 없다 | 출발지를 먼저 정하라고 알린다. `하루 설정` 으로 가는 길을 준다 | RBR-23 |
| 남은 일정이 없다 | 계산할 일정이 없다고 알린다 | RBR-26 |
| 옛 값도 없이 외부가 실패했다 | 어느 구간을 계산할 수 없는지 알린다 | RBR-32 |

### 받는 조작

| 조작 | 무슨 일이 일어나나 | 근거 |
|---|---|---|
| `새로 계산` | 캐시를 무르고 모두 다시 받는다 | RBR-29 |
| 일정을 끌어 놓아 순서를 옮긴다 | 그 자리가 고정되고 나머지만 다시 계산된다 | RBR-42 |
| 고정한 자리를 푼다 | 다시 앱이 정한 순서로 돌아간다 | RBR-6 |
| 일정을 누른다 | `schedule-core` 의 V-2 일정 상세가 열린다 | 기존 화면 |

### 순서를 손으로 옮길 때 (RBR-42 · RBR-43)

```
손으로 옮긴 자리         고정형은 옮길 수 없다 (RBR-2)
  ⋮ 장 보기      [고정 풀기]
  
손으로 잡은 순서가 늦게 되면
  ⚠ 이 순서로는 민수와 저녁에 20분 늦습니다. 그래도 두겠습니까?
  → 저장은 막지 않는다 (RBR-43)
```

앱이 정한 순서는 도착 불가면 내지 않지만(RBR-17), 사람이 정한 순서는 막지 않는다.
계산이 사람의 판단을 덮어써서는 안 된다.

## 장소 후보 고르기 — `PlaceInput` 을 채운다

`schedule-core` 가 만들어 둔 `PlaceInput` 에는 지금 "좌표는 아직 없습니다" 안내만 있다.
그 자리에 후보 찾기와 고르기를 넣는다 (Q2-C · RBR-35~RBR-38).

```
장소  [ 강남역 스타벅스        ]  [찾기]

후보가 여럿일 때 (RBR-36)
  ○ 스타벅스 강남대로점    서울 강남구 강남대로 396
  ○ 스타벅스 강남역점      서울 강남구 테헤란로 101
  ○ 스타벅스 강남C점       서울 강남구 강남대로 419
  → 하나를 골라야 확정된다

후보가 하나일 때 (RBR-37)
  ✓ 스타벅스 강남대로점    자동으로 확정했습니다

후보가 없을 때 (RBR-38)
  찾지 못했습니다. 주소를 다르게 적어보세요.
  이대로 저장하면 이 일정은 동선 계산에서 빠집니다.
```

| 규칙 | 화면에서 |
|---|---|
| RBR-36 여럿이면 골라야 확정 | 고르기 전에는 확정 표시가 없다 |
| RBR-37 하나면 자동 확정 | 고르는 절차 없이 확정 표시 |
| RBR-38 없으면 좌표를 비워 둔다 | 저장은 되고, 동선에서 빠진다고 알린다 |
| RBR-40 글자를 고치면 좌표가 지워진다 | 이미 `schedule-core` 에서 지키고 있다 (BR-24) |

## 하루 시작 시각 칸 — `DataPanel` 에 더한다

Q3-B 가 만든 값이다. 사용자가 바꾸는 값이므로 기존 설정 칸 옆에 놓는다 (BR-52).

```
앞날의 하루 시작 시각   [ 09:00 ]
  오늘 동선은 지금 시각을 씁니다. 앞날은 이 시각에 나간다고 보고 계산합니다.
```

이 칸이 없으면 앞날의 유연형 일정 시각을 계산할 방법이 없다 (RBR-8).

## 이미 있는 화면을 고치는 것 (Q4-C 기준)

| 무엇 | 왜 | 어느 경우에 해당하나 |
|---|---|---|
| `DayView` 의 동선 결과 자리를 V-3 로 채운다 | `schedule-core` 가 비워 두고 뒤 단위가 채우기로 예정했다 | 설계에 예정된 자리 |
| `PlaceInput` 에 후보 찾기·고르기를 넣는다 | BR-21 이 좌표 채우기를 이 단위로 넘겼다 | 설계에 예정된 자리 |
| `DataPanel` 에 하루 시작 시각 칸을 더한다 | Q3-B 가 요구한다. 기존 칸을 건드리지 않는다 | 깨지 않는 추가 |
| `DayView` 의 `좌표 없음` 안내 문구를 고친다 | Q4-A 로 "빼고 계산한다" 가 정해졌으니 "계산할 수 없다" 는 안내가 틀리게 된다 | 설계에 예정된 자리 |

넷 다 `그 자리에서 고친다` 에 해당한다. 되돌아가지 않는다.
