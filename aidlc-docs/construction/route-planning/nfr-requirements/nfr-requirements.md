# route-planning · 비기능 요구

> 근거: `requirements.md` NFR-1~NFR-5 · `functional-design/business-rules.md` (RBR-) · `tech-stack-decisions.md`
> 이 단위가 **지는 것만** 적는다. 번호는 `R-NFR-` 로 시작한다.

## 이 단위가 지는 것

### R-NFR-1: 성능 (NFR-1.1 · NFR-1.3)

- **R-NFR-1.1**: 일정 10개 기준으로 동선 결과가 3초 안에 나온다 (RBR-45)
- **R-NFR-1.2**: 같은 구간 · 같은 이동 수단은 캐시 유지 시간 안에서 외부를 부르지 않는다 (RBR-28)
- **R-NFR-1.3**: 한 번 계산하는 동안 같은 구간을 두 번 조회하지 않는다 (RBR-46)
- **R-NFR-1.4**: 외부 호출은 정해진 시간 안에 답이 없으면 포기한다. 그 시간은 설정에 둔다
- **R-NFR-1.5**: 재시도는 한 번만 한다. 여러 번 늘려가며 시도하면 R-NFR-1.1 을 넘긴다 (Q4-B)

Q1-B · Q2-C 를 고른 결과 조합 폭발이 없어져 R-NFR-1.1 을 맞추기 쉬워졌다.
유연형 n 개에 대해 최대 n(n−1)/2 번의 구간 조회가 필요하다. 10개면 45번이고 캐시가 있으면 그보다 적다.
도보 · 대중교통은 외부를 부르지 않으므로(Q3-B) 조회 횟수가 더 줄어든다.

### R-NFR-2: 정확성 (NFR-2.1 · NFR-2.3)

- **R-NFR-2.1**: 시간 고정형 일정의 도착 시각은 어떤 결과에서도 앱이 바꾸지 않는다 (RBR-2)
- **R-NFR-2.2**: 고정형 일정에 제때 닿을 수 없으면 순서를 주지 않고 경고만 준다 (RBR-17)
- **R-NFR-2.3**: 총 이동 시간에 기다린 시간을 넣지 않는다 (RBR-13)
- **R-NFR-2.4**: 시각 계산은 사용자의 표준시로 하고, 자정을 넘겨도 어긋나지 않는다 (RBR-14)
- **R-NFR-2.5**: 지난 날짜를 볼 때 지금 시각을 쓰지 않는다 (RBR-15)
- **R-NFR-2.6**: 캐시에서 구간을 견줄 때 좌표를 정해진 소수 자릿수까지만 본다. 같은 장소가 캐시에서 어긋나지 않게 한다 (RBR-30)

R-NFR-2.3 이 없으면 순서를 견줄 때 엉뚱한 답이 나온다. 기다린 시간이 짧은 순서를 좋다고 판단하게 된다.

### R-NFR-3: 검증 (NFR-3.1 · NFR-3.2)

- **R-NFR-3.1**: C-2 동선 계산은 이동 시간을 인자로 받는다. 대역을 넣으면 외부 없이 전부 검증된다
- **R-NFR-3.2**: `business-logic-model.md` 의 경계 상황 22가지가 모두 테스트로 확인된다
- **R-NFR-3.3**: 지금 시각을 주입해 검증한다. RBR-8 이 지금 시각에 매달려 있어 그렇지 않으면 테스트가 시간에 흔들린다
- **R-NFR-3.4**: 자체 계산(Q3-B)은 외부를 부르지 않는다. 좌표를 넣고 분이 나오는지 확인한다
- **R-NFR-3.5**: 캐시 · 실패 · 재시도 흐름은 "외부에 묻는 함수" 를 갈아끼워 확인한다. 실패를 일으켜 `cached` · `stale` 이 갈리는지 본다
- **R-NFR-3.6**: 외부 응답을 해석하는 부분은 저장해 둔 응답 예시로 따로 확인한다 — **이동 시간의 단위 · 좌표의 순서 · 결과가 없을 때의 모양** (Q5-C)

**R-NFR-3.6 은 키를 받기 전에 만들 수 없다.** 응답 예시를 얻을 수 없기 때문이다.
그 자리를 비워 두고 키를 받는 시점에 채운다. STEP 05 에서 이 사실을 남긴다.

### R-NFR-4: 보안 (NFR-4.1 · NFR-4.2)

- **R-NFR-4.1**: API 키는 소스에 넣지 않고 `.env.local` 에서 받는다. `.gitignore` 로 저장소에 올라가지 않게 한다 (RBR-33)
- **R-NFR-4.2**: **Vite 는 빌드할 때 키를 결과물에 박아 넣는다.** 브라우저로 내려가는 키는 감춰지지 않는다. 감춘 척하지 않고 문서에 남긴다 (Q2-A)
- **R-NFR-4.3**: `.env.local.example` 에 키 이름만 적고 값은 비워 둔다
- **R-NFR-4.4**: 주소 · 좌표는 지도 서비스 호출 밖으로 나가지 않는다 (NFR-4.2)
- **R-NFR-4.5**: 키가 없어도 앱이 멈추지 않는다. 창구가 실패로 다루고 자체 계산으로 넘어간다

R-NFR-4.2 를 **인터넷에 올릴 때 다시 봐야 한다.** Q3-A 로 배포하지 않기로 했기 때문에 지금은 감수한다.

### R-NFR-5: 유지보수 (NFR-5.1 · NFR-5.2 · NFR-5.3)

- **R-NFR-5.1**: `fetch` 를 부르는 곳은 `src/gateways/kakao/` 안에만 있다 (NFR-5.1)
- **R-NFR-5.2**: `src/domain/route/` 는 `gateways/` 와 `ui/` 를 가져오지 않는다 (NFR-5.3)
- **R-NFR-5.3**: 서비스를 갈아끼울 때 `mapGateway.ts` 의 경계면만 지키면 된다
- **R-NFR-5.4**: 이동 수단에 따라 실제 API 와 자체 계산으로 갈라 보내는 곳은 `compositeGateway.ts` 한 군데다
- **R-NFR-5.5**: 아래 수치는 `src/domain/settings/` 에만 있다 — 캐시 유지 시간 · 좌표 견줄 자릿수 · 앞날 하루 시작 시각 · 도보 평균 속도 · 대중교통 평균 속도 · 우회 계수 · 최소 이동 시간 · 호출 포기 시간 · 재시도 대기 시간

R-NFR-5.4 가 중요하다. Q1-B 와 Q3-B 가 만든 갈림(자동차는 실제 API, 도보·대중교통은 자체 계산)이
한 파일에 모인다. 나중에 대중교통 API 를 얻으면 그 파일만 고친다.

### R-NFR-6: 어림값을 감추지 않는다

Q3-B 를 고른 결과 생긴 요구다. 요구사항에는 없었다.

- **R-NFR-6.1**: 자체 계산으로 얻은 이동 시간을 **어림값이라고 화면에 표시한다** (Q3-B)
- **R-NFR-6.2**: 어림값과 외부에서 받은 값을 구간마다 구분해 보여준다
- **R-NFR-6.3**: 어림값이 섞인 동선의 총 이동 시간도 어림값임을 알린다

`requirements.md` FR-6.1 은 실시간 교통이 반영된 값을 요구한다. **자동차만 그렇게 되므로**
나머지가 어림값임을 사용자가 알아야 한다. 이것을 감추면 앱이 실제보다 정확한 척하게 된다.

## 요구사항과 어긋나는 것 — 한자리에 모아 둔다

앞선 결정들이 요구사항과 완전히 맞지 않는 지점이 둘 있다. 감추지 않고 여기 적는다.

| 요구 | 어긋난 정도 | 왜 | 어떻게 다루나 |
|---|---|---|---|
| FR-2.2 총 이동 시간 최소화 | 목표는 맞지만 **가장 짧은 순서를 보장하지 않는다** | Q2-C — 가까운 곳부터 이어 붙이는 방식 | 화면에 순서를 어떻게 정했는지 밝힌다 · 사용자가 손으로 옮길 수 있다 (RBR-42) |
| FR-6.1 실시간 교통 반영 | **자동차만 반영된다.** 도보 · 대중교통은 어림값 | Q1-B + Q3-B — 카카오 계열에 대중교통 API 를 확인하지 못했고 도보는 제휴가 필요하다 | 어림값을 화면에 표시한다 (R-NFR-6) · 창구를 나눠 두어 나중에 갈아끼운다 (R-NFR-5.4) |

둘 다 사용자가 답으로 고른 결과이고, 그 결과를 화면에서 감추지 않는 것으로 다룬다.
