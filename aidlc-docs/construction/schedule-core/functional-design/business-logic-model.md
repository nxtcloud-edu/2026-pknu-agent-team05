# schedule-core · 업무 흐름

> 근거: `domain-entities.md` (E-1~E-7) · `business-rules.md` (BR-1~BR-53) · `components.md` (C-1 · C-5 · C-6)
> 이 단위가 하는 계산은 **C-1 일정 펼치기** 하나다. 나머지는 보관과 꺼내기다.

## C-1 일정 펼치기 — 이 단위의 핵심 계산

날짜 하나를 받아 그날의 일정 목록을 만든다. 보관된 것은 세 갈래로 나뉘어 있고(Q4-C), 이것이 합치는 자리다.

### 받는 것과 주는 것

```
받는 것 :  날짜 하나
        +  그 날짜의 개별 일정들            (E-2 중 직접 넣은 것)
        +  반복 규칙 전부                  (E-3)
        +  예외 기록 전부                  (E-5)
        +  설정                            (E-7 — 기본 이동 수단)

주는 것 :  그 날짜의 일정 목록
             직접 넣은 것과 반복에서 펼쳐진 것이 섞여 있고,
             각자 `어디서 왔는지` 를 지니고 있다
```

### 어떤 순서로 하나

```
1. 그 날짜의 개별 일정을 모은다                    (E-2 · 직접 넣음)

2. 반복 규칙을 하나씩 본다                         (E-3)
   2-1. 그 날짜의 요일이 규칙의 요일과 같은가?         → 아니면 건너뛴다        BR-27
   2-2. 그 날짜가 `언제부터` 보다 앞선가?             → 그러면 건너뛴다        BR-31
   2-3. `언제까지` 가 있고 그 날짜를 지났나?          → 그러면 건너뛴다        BR-32
   2-4. 이 규칙 + 이 날짜에 예외 기록이 있나?         (E-5)
          · `건너뜀` 이면          → 펼치지 않는다                        BR-37
          · `고침` 이면            → 고쳐진 값을 덮어 펼친다               BR-38
          · 없으면                → 규칙의 값 그대로 펼친다               BR-34
   2-5. 펼친 일정에 `어디서 왔는지 = 반복에서 펼쳐짐 + 어느 규칙` 을 붙인다   E-2

3. 이동 수단이 비어 있는 일정에 설정의 기본값을 채운다                     BR-8

4. 완료 표시된 일정에 `동선 계산에서 빠질 것` 을 표시한다                  BR-15

5. 목록을 낸다
```

### 어떤 순서로 늘어놓나

펼친 목록의 순서는 **동선 순서가 아니다.** 동선 순서는 `route-planning` 이 정한다 (FR-2.1).
화면에 보여줄 순서만 정한다.

```
지정한 도착 시각이 있는 일정  →  시각이 이른 것부터
지정한 도착 시각이 없는 일정  →  그 뒤에, 넣은 순서대로
```

이유 — 시각이 정해진 것을 먼저 보여주면 하루의 뼈대가 눈에 들어온다. 유연형은 어차피 `route-planning` 이 자리를 옮긴다.

### 자정을 넘는 일정 (BR-49)

지정한 도착 시각에 머무는 시간을 더한 값이 자정을 넘어도 그 일정은 **받은 날짜에 그대로 속한다.**
다음 날짜로 옮기지 않는다. 다음 날짜를 펼칠 때 이 일정은 나오지 않는다.

### 경계 상황 — 완료 기준이 되는 것들

이 단위의 완료 기준은 아래가 다 맞는 것이다 (`unit-of-work.md` Q3-B).

| 상황 | 무엇이 나와야 하나 | 규칙 |
|---|---|---|
| 그 날짜에 아무것도 없다 | 빈 목록. 오류가 아니다 | — |
| 개별 일정만 있다 | 그것들만 | — |
| 반복 규칙이 그 요일에 해당한다 | 펼쳐진 일정이 들어 있다 | BR-27, BR-29 |
| 반복 규칙이 다른 요일이다 | 펼쳐지지 않는다 | BR-27 |
| `언제부터` 보다 앞선 날짜다 | 펼쳐지지 않는다 | BR-31 |
| `언제까지` 를 지난 날짜다 | 펼쳐지지 않는다 | BR-32 |
| `건너뜀` 예외가 있다 | 펼쳐지지 않는다 | BR-37 |
| `고침` 예외가 있다 | 고쳐진 값으로 펼쳐진다. 고쳐지지 않은 값은 규칙의 값 | BR-38 |
| 반복 규칙을 고쳤는데 다른 날짜에 예외가 있다 | 예외 있는 날짜는 예외를 따르고, 나머지는 고친 값을 따른다 | BR-34 |
| 이동 수단이 비어 있다 | 설정의 기본값이 채워져 있다 | BR-8 |
| 완료 표시된 일정이 있다 | 목록에 남아 있고 `빠질 것` 으로 표시돼 있다 | BR-15 |
| 좌표가 비어 있다 | 오류 없이 펼쳐진다 | BR-22 |
| 도착 시각 + 머무는 시간이 자정을 넘는다 | 받은 날짜에 그대로 속한다 | BR-49 |
| 같은 요일에 반복 규칙이 둘 있다 | 둘 다 펼쳐진다 | BR-28 |

## C-5 보관소 — 무엇을 언제 남기나

계산이 아니라 남기고 꺼내는 일이다. 무엇을 남기는지는 `domain-entities.md` E-2~E-7 에 있다.

### 남기는 시점

| 언제 | 무엇을 |
|---|---|
| 일정을 저장할 때 | 규칙 검사(BR-1~BR-8)를 지난 뒤에 남긴다. 검사에 걸리면 남기지 않는다 |
| 반복에서 펼쳐진 일정을 그날만 고칠 때 | 일정이 아니라 **예외 기록**을 남긴다 (BR-35) |
| 반복에서 펼쳐진 일정을 그날만 지울 때 | `건너뜀` 예외를 남긴다 (BR-36, BR-40) |
| 직접 넣은 일정을 지울 때 | 그 일정을 지운다. 딸린 참여자도 함께 (BR-10, BR-41) |
| 반복 규칙을 지울 때 | 딸린 예외 기록도 함께 지운다 (BR-33) |
| 하루 설정을 넣을 때 | 그 날짜에만 남긴다 (BR-18) |
| 전체 삭제할 때 | E-2~E-6 을 지우고 E-7 을 기본값으로 (BR-44). 확인을 먼저 받는다 (BR-45) |

### 고치기가 두 갈래로 갈리는 곳

같은 화면 조작이 `어디서 왔는지` 에 따라 다른 결과를 낸다. 이 단위에서 가장 틀리기 쉬운 대목이다.

```
사용자가 목록에서 일정 하나를 고쳤다
   │
   ├─ 어디서 왔는지 = 직접 넣음
   │     → 그 일정 자체를 고친다                            BR-41
   │
   └─ 어디서 왔는지 = 반복에서 펼쳐짐
         → 반복 규칙은 건드리지 않는다
         → 그 날짜 + 그 규칙에 `고침` 예외를 남긴다            BR-35
         → 이미 예외가 있으면 덮어쓴다                        BR-39
```

지우기도 같은 방식으로 갈린다 (BR-40, BR-41).
완료 표시도 반복에서 펼쳐진 것이면 `고침` 예외로 들어간다 (BR-17).

### 꺼내는 시점

| 언제 | 무엇을 |
|---|---|
| 날짜를 열 때 | 그 날짜의 개별 일정 · 반복 규칙 전부 · 예외 기록 전부 · 하루 설정 · 설정 → C-1 에 넘긴다 |
| 약속 일정을 열 때 | 그 일정에 딸린 참여자 (경계 3 · meetup-midpoint 가 쓴다) |
| 앱을 처음 열 때 | 설정. 없으면 기본값으로 만든다 |

## 경계 1 로 넘기기 — `route-planning` 에 무엇을 주나

C-1 이 펼친 목록에 하루 설정과 설정 값을 얹어 넘긴다 (`unit-of-work.md` 경계 1).

```
C-1 펼친 목록  +  E-4 하루 설정  +  E-7 설정 값  ─────▶  route-planning
```

| 이 단위가 하는 것 | 이 단위가 하지 않는 것 |
|---|---|
| 반복과 예외를 합쳐 목록을 만든다 | 순서를 정하지 않는다 (FR-2.1) |
| 이동 수단 기본값을 채운다 | 이동 시간을 구하지 않는다 (C-7) |
| 완료된 것을 `빠질 것` 으로 표시한다 | 걸러내지 않는다 — `route-planning` 이 걸러낸다 |
| 좌표를 담을 자리를 만든다 | 좌표를 채우지 않는다 (BR-21) |

## 경계 3 로 넘기기 — `meetup-midpoint` 와 주고받기

```
schedule-core ──▶ meetup-midpoint     약속인 일정 하나 + 딸린 참여자들 + 설정 값
schedule-core ◀── meetup-midpoint     확정된 약속 장소 · 참여자 추가·수정·삭제
```

참여자를 보관하는 곳은 이 단위다 (E-6). `meetup-midpoint` 는 자기 보관소를 만들지 않는다.
확정된 장소가 들어오면 그 일정의 장소(E-1)를 바꾸고, 계산 결과는 `다시 계산해야 함` 이 된다 (BR-11).
