# schedule-core · 다루는 것들

> 근거: `unit-of-work.md` (schedule-core · 경계 1 · 경계 3) · `components.md` (C-5 · C-6) · `stories.md` (S-1~S-6, S-16)
> 답: Q1-A (반복은 요일만) · Q2-C (글자 입력 + 후보 고르기) · Q3-A (도착 시각 + 머무는 시간) · Q4-B (하루 설정은 날짜마다) · Q5-A (지난 날짜 그대로 남김)
> **여기서 언어 · 프레임워크 · 저장 기술을 고르지 않는다.** 값의 의미와 관계만 적는다. 자료형과 이름은 STEP 02 이후에 정한다.

## 한눈에 보기

```
설정 (하나뿐)
하루 설정 ── 날짜마다 하나 (Q4-B)
일정 ─────── 날짜 하나에 여러 개
반복 규칙 ── 요일 하나에 여러 개 (Q1-A)
예외 기록 ── 반복 규칙 + 날짜 하나에 하나
참여자 ───── 약속인 일정 하나에 여러 개 (경계 3 · meetup-midpoint 가 쓴다)
```

보관되는 것과 계산되는 것을 가른다. **보관되는 것만 아래에 있다.**
동선 순서 · 구간별 시각 · 출발 시각은 계산 결과이므로 보관하지 않는다 (route-planning · departure-alarm).

## E-1. 장소

일정 · 하루 설정 · 참여자 출발지가 모두 이것을 쓴다. 따로 보관되지 않고 다른 것에 딸려 있다.

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 사용자가 넣은 글자 | 사용자가 직접 친 주소나 장소 이름 (Q2-C) | 아니오 |
| 확정된 이름 | 후보 중 고른 것의 이름. 후보가 하나면 그것 | 예 — 아직 고르지 않았으면 |
| 좌표 | 위도 · 경도 | 예 — 아래 설명 참고 |
| 좌표를 얻은 시각 | 언제 변환된 값인지 | 좌표가 비어 있으면 함께 빈다 |

### 좌표가 비어 있을 수 있는 이유

주소를 좌표로 바꾸는 일은 **C-7 지도 창구**가 하고, 그것은 `route-planning` 단위 소유다 (`components.md`).
`schedule-core` 는 좌표를 담을 자리를 만들고, 글자와 확정된 이름을 보관한다. 좌표를 채우는 것은 `route-planning` 이 선 뒤다.

이 단위만 서 있는 동안에는 좌표 없이도 일정을 넣고 펼치고 보관하는 일이 다 된다.
경계 1 이 `route-planning` 에 좌표를 넘겨야 하므로, **좌표를 채우는 책임은 `route-planning` 에 있다** (BR-21 참고).

## E-2. 일정

하루에 갈 곳 하나다. 사용자가 직접 넣은 것과 반복에서 펼쳐진 것이 같은 모양이다.

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 가리키는 이름 | 이 일정을 다른 일정과 구별하는 것 | 아니오 |
| 날짜 | 어느 날의 일정인지 | 아니오 |
| 제목 | 무엇을 하는 일정인지 | 아니오 |
| 장소 | E-1 | 아니오 |
| 머무는 시간 | 그곳에서 얼마나 있는지 (분) | 아니오 |
| 유형 | `시간 고정형` 또는 `유연형` (FR-1.3) | 아니오 |
| 지정한 도착 시각 | 사용자가 정한 도착해야 하는 시각 (Q3-A) | **예** — 유연형이면 비어 있다 |
| 이동 수단 | 도보 · 대중교통 · 자동차 (FR-1.5) | 아니오 — 고르지 않으면 설정의 기본값이 채워진다 |
| 완료 표시 | 다녀왔는지 (FR-1.6) | 아니오 — 처음엔 아니다 |
| 손으로 고정한 자리 | 사용자가 순서를 직접 잡았다면 몇 번째인지 (FR-2.6) | 예 — 잡지 않았으면 비어 있다 |
| 약속인지 | 참여자가 딸리는 일정인지 (FR-3.1) | 아니오 — 처음엔 아니다 |
| 어디서 왔는지 | `직접 넣음` 또는 `반복에서 펼쳐짐` + 어느 반복 규칙인지 | 아니오 |

### Q3-A 를 어떻게 담았나

시각을 다루는 값은 `지정한 도착 시각` 과 `머무는 시간` 둘이다. 끝나는 시각은 보관하지 않고 필요할 때 더해 구한다.

- **시간 고정형** — `지정한 도착 시각` 이 채워져 있다. 앱은 이 시각을 바꾸지 않는다 (FR-2.3)
- **유연형** — `지정한 도착 시각` 이 비어 있다. 실제 도착 시각은 `route-planning` 이 계산해 낸다 (FR-1.3)

유형에 따라 지닌 값의 종류가 달라지지 않는다. 같은 모양을 쓰고 한 칸이 비는 것으로 갈린다.

### `어디서 왔는지` 가 필요한 이유

반복에서 펼쳐진 일정을 고치거나 건너뛰면 **예외 기록**(E-5)을 남겨야 한다.
직접 넣은 일정을 고치면 그 일정 자체를 고친다. 둘을 구별해야 어느 쪽인지 알 수 있다 (FR-1.9).

## E-3. 반복 규칙 (Q1-A)

되풀이되는 일정을 규칙 하나로 둔다. **미래 날짜의 일정을 미리 만들지 않는다.**

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 가리키는 이름 | 이 규칙을 구별하는 것. 펼쳐진 일정이 이것을 가리킨다 | 아니오 |
| 무슨 요일 | 월~일 중 하나 (Q1-A — 요일만) | 아니오 |
| 제목 · 장소 · 머무는 시간 · 유형 · 지정한 도착 시각 · 이동 수단 | 펼쳐질 일정에 그대로 들어갈 값들 | E-2 와 같은 규칙 |
| 언제부터 | 이 규칙이 시작되는 날짜 | 아니오 |
| 언제까지 | 이 규칙이 끝나는 날짜 | 예 — 끝이 없으면 비어 있다 |

Q1-A 를 골랐으므로 `매일` · `격주` · `매월 며칠` 은 없다. 요일 하나만 지정한다.
"매주 화요일과 목요일"을 원하면 규칙을 둘 만든다.

## E-4. 하루 설정 (Q4-B)

하루의 시작점과 끝점이다. **날짜마다 따로** 둔다.

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 날짜 | 어느 날의 설정인지 | 아니오 |
| 출발지 | E-1. 하루가 시작되는 곳 (FR-1.7) | 아니오 |
| 마지막 도착지 | E-1. 하루가 끝나는 곳 | **예** — 비어 있으면 돌아오는 구간을 계산에 넣지 않는다 (S-4) |

Q4-B 를 골랐으므로 날짜마다 넣는다. 새 날짜를 열면 하루 설정이 없는 상태로 시작한다.

## E-5. 예외 기록

반복에서 펼쳐질 일정 하나를 그 날짜에만 다르게 다루는 기록이다 (FR-1.9).

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 어느 반복 규칙 | E-3 을 가리킨다 | 아니오 |
| 어느 날짜 | 그 규칙이 그날 펼쳐질 자리 | 아니오 |
| 어떻게 | `건너뜀` 또는 `고침` | 아니오 |
| 고쳐진 값 | `고침` 이면 무엇이 어떻게 바뀌는지 (제목 · 장소 · 머무는 시간 · 유형 · 지정한 도착 시각 · 이동 수단 중 바뀐 것만) | `건너뜀` 이면 비어 있다 |

`어느 반복 규칙 + 어느 날짜` 조합은 하나뿐이다. 같은 자리에 예외가 둘 있을 수 없다.

## E-6. 참여자 (경계 3)

약속인 일정에 딸린다. **보관하는 곳은 이 단위이고, 쓰는 곳은 `meetup-midpoint` 다.**

| 값 | 의미 | 비어 있을 수 있나 |
|---|---|---|
| 어느 일정 | E-2 를 가리킨다. 그 일정은 `약속인지` 가 참이어야 한다 | 아니오 |
| 이름 | 누구인지 | 아니오 |
| 출발지 | E-1. 어디서 오는지 (FR-3.1) | 아니오 |
| 이동 수단 | 도보 · 대중교통 · 자동차 (FR-3.5) | 아니오 — 설정의 기본값이 채워진다 |

`components.md` C-5 ⑤ 에 이미 예정된 자리다. 이 단위에서 자리를 만들어 두면 `meetup-midpoint` 가 되돌아오지 않아도 된다 (Q4-C 기준).

## E-7. 설정 (C-6)

수치를 모아 두는 자리다. 하나만 있다 (NFR-5.2).

| 값 | 의미 | 누가 쓰나 | 사용자가 바꾸나 |
|---|---|---|---|
| 여유 시간 기본값 | 출발 시각을 얼마나 앞당길지 (분) | departure-alarm | 예 (FR-5.3) |
| 기본 이동 수단 | 고르지 않은 일정에 채울 값 | 이 단위 · meetup-midpoint | 예 (S-3) |
| 이동 시간 캐시 유지 시간 | 같은 구간을 다시 묻지 않는 기간 | route-planning | 아니오 |
| 장소 검색 반경 | 중간지점 주변을 얼마나 넓게 볼지 | meetup-midpoint | 예 (S-13 — 넓혀 다시 찾기) |
| 중간지점 후보 개수 | 몇 개까지 견줄지 | meetup-midpoint | 아니오 |

이 단위는 `기본 이동 수단` 만 실제로 쓴다. 나머지는 자리를 만들어 두고 뒤 단위가 읽는다.
사용자가 바꾸는 값과 앱이 정하는 값을 갈라 둔다.

## 무엇을 보관하지 않나

| 보관하지 않는 것 | 어디서 나오나 |
|---|---|
| 동선 순서 | route-planning 이 계산한다 |
| 구간별 출발 · 도착 시각 · 이동 시간 | route-planning |
| 출발 시각 · 알림 시각 | departure-alarm |
| 중간지점 좌표 | meetup-midpoint 가 계산한다. 확정되면 그 일정의 장소(E-1)로 들어온다 |
| 장소 후보 목록 | meetup-midpoint 가 조회한다. 고른 것만 장소로 들어온다 |
| 반복에서 펼쳐진 미래 일정 | C-1 이 볼 때 펼친다 (Q4-C · E-3) |

계산 결과를 보관하지 않는 이유는 일정이 바뀌면 어긋나기 때문이다. 볼 때 다시 계산한다.

## 지난 날짜 (Q5-A)

지난 날짜의 일정을 지우지 않는다. 날짜를 거슬러 가면 그대로 보인다.
지우는 기간을 두지 않으므로 E-7 설정에 보관 기간 값이 없다.
