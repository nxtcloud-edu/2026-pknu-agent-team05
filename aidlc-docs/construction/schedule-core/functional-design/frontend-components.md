# schedule-core · 화면

> 근거: `components.md` V-1 · V-2 · V-7 · V-9 (Q1-C 하루 보기 + 패널) · `business-rules.md` · `domain-entities.md`
> **여기서 프레임워크 · 컴포넌트 라이브러리를 고르지 않는다.** 무엇을 보여주고 무엇을 받는지만 적는다.
> 이 단위가 만드는 화면은 넷이다. 나머지 화면(V-3 동선 결과 · V-4~V-6 약속 · V-8 알림)은 뒤 단위가 만든다.

## 화면 짜임 (Q1-C)

하루 보기 하나가 늘 떠 있고, 나머지는 그 위에 열리는 패널이다. 화면을 옮겨 다니지 않는다.

```
┌──────────────────────────────────────────────────────┐
│  V-1 하루 보기                                        │
│  ┌────────────────────────────────────────────────┐  │
│  │ 날짜 고르기   ◀ 8월 26일 (수) ▶                  │  │
│  ├────────────────────────────────────────────────┤  │
│  │ 하루 설정 요약   집 → … → 집        [고치기]      │  │  ▶ V-7 열림
│  ├────────────────────────────────────────────────┤  │
│  │ 일정 목록                                       │  │
│  │  ⏰ 14:00  치과            60분  대중교통  [ ]    │  │  ▶ V-2 열림
│  │  ↻ ⏰ 19:00  헬스          90분  도보     [ ]    │  │
│  │  ○  —      장 보기        30분  자동차   [✓]    │  │
│  │  [+ 일정 넣기]                                  │  │  ▶ V-2 열림
│  ├────────────────────────────────────────────────┤  │
│  │ 동선 결과 자리 — route-planning 이 채운다         │  │
│  └────────────────────────────────────────────────┘  │
│  [데이터 관리]                                        │  ▶ V-9 열림
└──────────────────────────────────────────────────────┘
```

패널은 하루 보기를 덮지 않고 옆이나 아래에 열린다. 한 번에 하나만 열린다.

---

## V-1 하루 보기

### 보여주는 것

| 무엇 | 어디서 오나 |
|---|---|
| 고른 날짜 | 화면이 쥔다. 처음 열면 오늘 |
| 그 날짜의 일정 목록 | C-1 펼치기 결과 |
| 하루 설정 요약 (출발지 → 마지막 도착지) | E-4 |
| 계산 결과가 `다시 계산해야 함` 인지 | BR-11~BR-13 |
| 동선 결과 자리 | 비워 둔다 — `route-planning` 이 채운다 |

### 일정 한 줄에 보이는 것

```
⏰ 14:00  치과        60분  대중교통  [ ]
│  │      │          │     │        └ 완료 표시 (누르면 바뀐다)
│  │      │          │     └ 이동 수단
│  │      │          └ 머무는 시간
│  │      └ 제목
│  └ 지정한 도착 시각 — 고정형만. 유연형은 `—`
└ 유형 표시 — ⏰ 고정형 / ○ 유연형        (S-2 · 구분되어 보여야 한다)

↻ 가 앞에 붙으면 반복에서 펼쳐진 일정      (E-2 어디서 왔는지)
```

- 유형이 눈에 보이게 갈라야 한다 (S-2 수락 기준)
- 반복에서 온 것을 표시하는 이유 — 고치면 그 날짜만 바뀐다는 것을 사용자가 알아야 한다 (BR-35)
- 완료된 줄은 흐리게. 목록에서 사라지지 않는다 (BR-15)
- 제목 · 장소는 글자로만 그린다 (BR-9)

### 받는 조작

| 조작 | 무슨 일이 일어나나 |
|---|---|
| 날짜를 앞뒤로 옮긴다 | 그 날짜를 C-1 로 펼쳐 다시 그린다. 지난 날짜도 볼 수 있다 (Q5-A) |
| 일정 줄을 누른다 | V-2 가 그 일정을 들고 열린다 |
| `+ 일정 넣기` | V-2 가 빈 상태로 열린다 |
| 완료 표시를 누른다 | BR-15~BR-17. 반복에서 온 것이면 `고침` 예외로 남는다 |
| 하루 설정 `고치기` | V-7 이 열린다 |
| `데이터 관리` | V-9 가 열린다 |

### 알려야 하는 것

| 상황 | 무엇을 보여주나 |
|---|---|
| 출발지가 없다 | 동선을 계산할 수 없다는 것과 출발지를 먼저 넣으라는 안내 (BR-19) |
| 일정이 없다 | 빈 목록임을 알리는 안내. 오류가 아니다 |
| 계산 결과가 낡았다 | 다시 계산해야 함을 표시 (BR-11~BR-13) |
| 장소에 좌표가 없다 | 그 일정에 표시. 동선 계산에 쓸 수 없음을 알린다 (BR-21, BR-22) |

## V-2 일정 상세 패널

일정을 넣고 고친다. 빈 상태로 열리면 새로 넣는 것이고, 일정을 들고 열리면 고치는 것이다.

### 받는 칸

| 칸 | 규칙 |
|---|---|
| 제목 | 비우면 저장 안 됨 (BR-1) |
| 장소 | 글자를 친다. 비우면 저장 안 됨 (BR-2). 아래 `장소 고르기` 참고 |
| 머무는 시간 | 0보다 커야 한다 (BR-3) |
| 유형 | `시간 고정형` / `유연형` 중 하나 (FR-1.3) |
| 지정한 도착 시각 | **고정형을 고르면 나타나고 필수다** (BR-4). 유연형을 고르면 사라진다 (BR-5, BR-6) |
| 이동 수단 | 도보 · 대중교통 · 자동차. 고르지 않으면 설정 기본값 (BR-8) |
| 반복 | 끄거나, 요일 하나를 고른다 (BR-27). 아래 `반복 켜기` 참고 |
| 약속인지 | 켜면 참여자를 넣을 수 있다 — 실제 참여자 칸은 `meetup-midpoint` 가 만든다 (V-4) |

### 장소 고르기 (Q2-C)

```
장소  [ 강남역 스타벅스        ]  [찾기]
      ┌──────────────────────────────┐
      │ ○ 스타벅스 강남대로점         │   후보가 여럿이면 골라야 확정 (BR-25)
      │ ○ 스타벅스 강남역점           │
      │ ○ 스타벅스 강남C점            │
      └──────────────────────────────┘
```

- 후보 조회는 **`route-planning` 의 C-7 이 선 뒤에 이어진다** (BR-21). 이 단위에서는 고르는 흐름과 담을 자리만 만든다
- 후보가 하나면 자동으로 확정된다 (BR-26)
- 고르기 전에는 확정된 이름이 비어 있고, 그 상태로도 저장은 된다 (BR-22)
- 글자를 고치면 좌표와 확정된 이름이 지워진다 (BR-24)

### 반복 켜기 (Q1-A)

```
반복  [ ] 끔
      [✓] 매주  [화] 요일         요일 하나만 (BR-27)
      언제부터  [ 2026-08-26 ]
      언제까지  [           ]     비워 두면 끝이 없다
```

여러 요일에 되풀이하려면 일정을 여러 번 넣는다 (BR-28). 화면에서 요일을 여러 개 고를 수 없다.

### 반복에서 온 일정을 고칠 때 (BR-35)

패널 위에 무엇이 일어나는지 미리 알린다. 저장한 뒤에 알면 늦다.

```
↻ 이 일정은 매주 화요일 반복에서 나왔습니다.
  고치면 8월 26일 하루만 바뀝니다. 다음 주 화요일은 그대로입니다.
```

지우기를 누를 때도 같은 안내를 한다 — 그 날짜만 건너뛰는 것이다 (BR-36, BR-40).

### 저장할 때

- 규칙 검사(BR-1~BR-8)에 걸리면 저장하지 않고, **어느 칸이 왜 잘못됐는지** 그 칸 옆에 보여준다 (S-1)
- 저장되면 패널이 닫히고 V-1 이 다시 그려진다
- 계산 결과는 `다시 계산해야 함` 이 된다 (BR-11, BR-12)

## V-7 하루 설정 패널

날짜 하나의 출발지와 마지막 도착지를 정한다 (Q4-B).

| 칸 | 규칙 |
|---|---|
| 출발지 | 필수 (BR-19). 장소 고르기는 V-2 와 같다 |
| 마지막 도착지 | 비워 둘 수 있다. 비우면 돌아오는 구간을 계산하지 않는다 (BR-20) |

### 이 패널이 알려야 하는 것

Q4-B 를 골랐으므로 하루 설정은 **날짜마다 따로**다. 다른 날짜에 반영되지 않는다 (BR-18).
새 날짜를 열면 하루 설정이 비어 있다. 사용자가 이것을 모르면 매번 왜 비어 있는지 의아해진다.

```
이 설정은 8월 26일에만 적용됩니다. 다른 날짜는 따로 정해야 합니다.
```

저장하면 그 날짜의 계산 결과가 `다시 계산해야 함` 이 된다 (BR-13).

## V-9 데이터 관리 패널

| 무엇 | 규칙 |
|---|---|
| 보관된 것 요약 | 일정 몇 개 · 반복 규칙 몇 개 · 며칠분 |
| 전체 삭제 | E-2~E-6 을 지우고 E-7 을 기본값으로 (BR-44) |
| 설정 고치기 | 사용자가 바꾸는 값만 — 여유 시간 기본값 · 기본 이동 수단 · 장소 검색 반경 (BR-52) |

### 전체 삭제 확인 (BR-45)

```
일정 · 반복 규칙 · 참여자 정보가 모두 지워집니다.
이 브라우저에만 저장돼 있어 되돌릴 수 없습니다.

[취소]  [지운다]
```

되돌릴 수 없음을 반드시 먼저 알린다 (NFR-4.4). 브라우저에만 저장된다는 사실이 이유다 (Q9-A).

여유 시간 기본값과 장소 검색 반경은 이 단위에서 쓰이지 않지만, 설정 칸을 여기 만들어 둔다.
뒤 단위(`departure-alarm` · `meetup-midpoint`)가 그 값을 읽는다 (BR-53).

## 패널이 열리고 닫히는 규칙

| 규칙 | 왜 |
|---|---|
| 한 번에 패널 하나만 열린다 | 하루 보기 맥락을 잃지 않는다 (Q1-C) |
| 패널이 열려 있어도 하루 보기는 보인다 | 고치는 대상이 목록에서 어디인지 보여야 한다 |
| 저장하거나 취소하면 닫힌다 | — |
| 저장하지 않은 채 다른 패널을 열려 하면 확인을 받는다 | 넣던 내용이 사라지는 것을 막는다 |
| 날짜를 옮기면 열린 패널이 닫힌다 | 다른 날짜의 일정을 고치고 있는 상태가 되면 헷갈린다 |

## 이 단위에서 만들지 않는 화면

| 화면 | 어느 단위 |
|---|---|
| V-3 동선 결과 — 구간별 시각 · 도착 불가 경고 · 순서 옮기기 | route-planning |
| V-8 알림 상태 — 권한 안내 · 예약된 알림 목록 | departure-alarm |
| V-4 약속 참여자 칸 · V-5 중간지점 결과 · V-6 장소 후보 | meetup-midpoint |

V-1 에 동선 결과 자리를 비워 두고, V-2 에 `약속인지` 스위치만 만들어 둔다.
뒤 단위가 그 자리를 채운다. 자리를 미리 만들어 두므로 되돌아올 일이 없다 (Q4-C 기준).

## 화면 확인은 언제 하나 (Q3-B)

이 단위의 완료 기준은 C-1 펼치기 계산 테스트다. 화면은 이 단위의 완료 기준에 들어가지 않는다.
V-1 · V-2 · V-7 · V-9 가 제대로 그려지는지는 CONSTRUCTION STEP 06 빌드와 테스트에서 손으로 확인한다.
