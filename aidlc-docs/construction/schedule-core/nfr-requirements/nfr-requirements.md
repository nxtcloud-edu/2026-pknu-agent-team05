# schedule-core · 비기능 요구

> 근거: `requirements.md` NFR-1~NFR-5 · `functional-design/business-rules.md` · `tech-stack-decisions.md`
> 이 단위가 **지는 것만** 적는다. 나머지는 어느 단위가 지는지 아래 표로 넘긴다.

## 이 단위가 지는 것

### U-NFR-1: 시각 다루기 (NFR-2.3)

- **U-NFR-1.1**: 날짜와 시각은 사용자의 표준시로 다룬다. UTC 로 바꿔 저장하고 되돌리는 과정에서 날짜가 하루 밀리지 않아야 한다 (BR-48)
- **U-NFR-1.2**: 지정한 도착 시각 + 머무는 시간이 자정을 넘어도 그 일정은 원래 날짜에 속한다 (BR-49)
- **U-NFR-1.3**: `localStorage` 는 글자만 담는다. 시각을 글자로 바꿔 넣고 꺼내 되돌린 값이 넣기 전과 같아야 한다

U-NFR-1.3 은 Q2-A 를 고른 결과 생긴 요구다. 저장 방식이 시각을 글자로 만들기 때문에 여기서 어긋나기 쉽다.

### U-NFR-2: 검증 (NFR-3.1 · NFR-3.2)

- **U-NFR-2.1**: C-1 일정 펼치기는 외부 서비스나 브라우저 없이 테스트로 돌아간다
- **U-NFR-2.2**: `business-logic-model.md` 의 경계 상황 14가지가 모두 테스트로 확인된다 — 빈 목록 · 요일 불일치 · `언제부터` 이전 · `언제까지` 이후 · 건너뜀 예외 · 고침 예외 · 규칙 수정과 예외 공존 · 이동수단 기본값 · 완료 표시 · 좌표 없음 · 자정 넘김 · 같은 요일 규칙 둘
- **U-NFR-2.3**: 규칙 검사(BR-1~BR-8)가 각각 테스트로 확인된다
- **U-NFR-2.4**: 테스트는 감시 모드가 아니라 한 번 돌고 끝난다 (`npm test`)

이 단위의 완료 기준이 U-NFR-2 다 (`unit-of-work.md` Q3-B).

### U-NFR-3: 보안 (NFR-4.2 · NFR-4.3 · NFR-4.4)

- **U-NFR-3.1**: 사용자와 참여자가 넣은 글자는 화면에 그릴 때 글자로만 다룬다. 코드로 실행되지 않는다 (BR-9)
- **U-NFR-3.2**: 참여자의 이름 · 주소 · 좌표는 브라우저 밖으로 나가지 않는다. 이 단위는 외부를 부르지 않으므로 나갈 통로가 없다 (BR-46)
- **U-NFR-3.3**: 전체 삭제는 E-2~E-6 을 모두 지우고 E-7 을 기본값으로 되돌린다 (BR-44)
- **U-NFR-3.4**: 전체 삭제 전에 되돌릴 수 없음을 알리고 확인을 받는다 (BR-45)

### U-NFR-4: 유지보수 (NFR-5.2 · NFR-5.3)

- **U-NFR-4.1**: 수치는 `domain/settings/` 에만 있다. 계산 코드와 화면 코드에 숫자를 박지 않는다 (BR-51)
- **U-NFR-4.2**: `domain/` 은 `ui/` 를 가져오지 않는다. 의존은 화면 → 계산 한 방향이다 (NFR-5.3)
- **U-NFR-4.3**: `localStorage` 를 직접 부르는 곳은 `storage/localStore.ts` 한 군데다. 저장 방식을 바꿀 때 고칠 지점이 하나다
- **U-NFR-4.4**: 사용자가 바꾸는 값과 앱이 정하는 값을 갈라 둔다 (BR-52)

### U-NFR-5: 이 단위만으로 서는 것

- **U-NFR-5.1**: 좌표가 비어 있어도 일정을 넣고 고치고 펼치고 보관하는 일이 모두 된다 (BR-22)
- **U-NFR-5.2**: `route-planning` 이 없어도 이 단위의 화면 넷이 동작한다. 동선 결과 자리는 비어 있다
- **U-NFR-5.3**: 뒤 단위가 쓸 자리를 미리 만들어 둔다 — E-6 참여자 · E-7 의 여유 시간 · 반경 · 캐시 유지 시간. 그래야 뒤 단위가 되돌아오지 않는다

U-NFR-5 는 요구사항에 없던 것이다. 단위를 넷으로 쪼갠 결과 생긴 요구다.

## 성능에 대해

`requirements.md` 의 성능 기준(NFR-1.1 · NFR-1.2)은 이 단위에 걸리지 않는다.
다만 C-1 펼치기는 날짜를 옮길 때마다 돌아간다. 반복 규칙과 예외 기록 전부를 훑으므로, 규칙이 많아지면 느려질 수 있다.
지금은 기준을 두지 않는다. 규칙 수십 개 수준에서 문제가 되지 않기 때문이다. CONSTRUCTION 06 에서 체감이 느리면 그때 기준을 세운다.

## Q2-A 가 만든 위험

`localStorage` 를 고른 결과 아래 두 가지를 STEP 05 에서 주의한다.

| 위험 | 어떻게 다루나 |
|---|---|
| 시각이 글자로 오가며 어긋난다 | U-NFR-1.3 을 테스트로 확인한다 |
| 저장된 것과 코드가 기대하는 모양이 어긋난다 (나중에 값을 추가하면) | 저장할 때 모양의 판번호를 함께 넣고, 꺼낼 때 다르면 빈 값으로 시작한다. 지금은 판번호만 넣어 두고 옮기는 일은 하지 않는다 |
