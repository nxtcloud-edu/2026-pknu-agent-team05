## 큰 그림 — 두 층 (Q2-A)

층은 둘이다. 화면과, 그 밖의 모든 것.
층이 둘이라도 아래 층 안은 여러 구성 요소로 나뉜다. 층 수와 구성 요소 분리는 다른 이야기다.

```
┌─────────────────────────────────────────────────┐
│  층 1 · 화면                                     │
│  하루 보기 + 필요할 때 열리는 패널들 (Q1-C)        │
└───────────────────┬─────────────────────────────┘
                    │ 화면은 아래에 "해달라"고만 한다.
                    │ 계산식을 직접 갖지 않는다. (NFR-5.3)
┌───────────────────▼─────────────────────────────┐
│  층 2 · 그 밖의 모든 것                           │
│                                                 │
│  [계산]   C-1 일정 펼치기                        │
│           C-2 동선 계산                          │
│           C-3 중간지점 계산                       │
│           C-4 출발시각 계산과 알림 예약           │
│                                                 │
│  [보관]   C-5 일정 보관소                        │
│           C-6 설정                               │
│                                                 │
│  [창구]   C-7 지도 창구 (주소↔좌표 · 길찾기)      │
│           C-8 장소 창구 (장소 검색)               │
└─────────────────────────────────────────────────┘
```

### 이 그림이 지키는 것

| 요구 | 어떻게 지켜지나 |
|---|---|
| NFR-5.3 계산과 화면 분리 | 계산은 C-1~C-4 에만 있다. 화면은 결과를 받아 그리기만 한다 |
| NFR-5.1 외부 접근 경계 분리 | 외부와 닿는 곳은 C-7 · C-8 두 군데뿐이다. 계산 요소는 외부를 직접 부르지 않는다 |
| NFR-5.2 규칙과 숫자 분리 | 수치는 C-6 에 모은다. 계산 요소는 C-6 에서 받아 쓴다 |

## 층 1 · 화면 (Q1-C)

하루 보기 하나를 기본으로 두고, 나머지는 그 위에 열리는 패널이다. 화면을 옮겨 다니지 않는다.

| 이름 | 무엇을 책임지나 | 스토리 |
|---|---|---|
| V-1 하루 보기 | 날짜 하나를 골라 그날의 일정 목록과 계산된 동선을 보여준다. 앱의 기본 화면 | S-1, S-5, S-8 |
| V-2 일정 상세 패널 | 일정 하나를 넣고 고친다 — 제목 · 장소 · 머무는 시간 · 유형(고정/유연) · 도착 시각 · 이동 수단 · 반복 | S-1, S-2, S-3, S-16 |
| V-3 동선 결과 표시 | 구간별 출발 · 도착 시각 · 이동 시간 · 이동 수단. 도착 불가 경고. 순서를 손으로 옮기는 조작 | S-8, S-9, S-10 |
| V-4 약속 패널 | 일정을 약속으로 지정하고 참여자 이름 · 출발지 · 이동 수단을 넣는다 | S-11 |
| V-5 중간지점 결과 패널 | 계산된 중간지점과 참여자별 예상 이동 시간 | S-12 |
| V-6 장소 후보 패널 | 중간지점 주변 후보 목록. 카테고리 걸러보기. 하나를 골라 확정 | S-13, S-14 |
| V-7 하루 설정 | 하루의 출발지와 마지막 도착지 | S-4 |
| V-8 알림 상태 안내 | 알림 권한이 없을 때 그 사실과 켜는 방법. 예약된 알림 목록 | S-15 |
| V-9 데이터 관리 | 전체 삭제. 되돌릴 수 없다는 경고 | S-6 |

화면이 지켜야 하는 것 — 사용자가 넣은 글자는 그릴 때 글자로만 다루고 코드로 실행되지 않게 한다 (NFR-4.3, S-1).

## 층 2 · 구성 요소

### C-1 일정 펼치기

**책임** — 보관된 것을 그날 하루치 일정 목록으로 펼친다. Q4-C 가 요구하는 합치기 단계다.

보관소에는 세 가지가 따로 들어 있다 (C-5). 그것을 날짜 하나에 대해 합친다.

```
받는 것 :  날짜
        +  그날 직접 넣은 일정들
        +  반복 규칙들
        +  예외 기록들 (건너뜀 · 그날만 고침)

주는 것 :  그날의 일정 목록 (직접 넣은 것과 반복에서 나온 것이 섞여 있고,
                          어느 쪽에서 왔는지 구분은 남아 있다)
```

**규칙**
- 반복 규칙이 그 날짜에 해당하면 일정 하나를 만들어 넣는다 (FR-1.8)
- 그 날짜에 `건너뜀` 예외가 있으면 넣지 않는다 (FR-1.9)
- 그 날짜에 `고침` 예외가 있으면 고쳐진 값으로 넣는다 (FR-1.9)
- 완료 표시된 일정은 목록에 남기되 **동선 계산에서 빠질 것**으로 표시한다 (FR-1.6, S-5)
- 반복에서 나온 일정도 직접 넣은 일정과 똑같이 다뤄진다 (S-16)

### C-2 동선 계산

**책임** — 일정 목록을 받아 순서와 구간별 시각을 정한다. 앱의 핵심 계산이다.

```
받는 것 :  그날의 일정 목록 (완료된 것 제외)
        +  하루의 출발지 · 마지막 도착지
        +  구간별 이동 시간 (C-7 이 구해 준 값. 이 요소가 직접 외부를 부르지 않는다)

주는 것 :  순서 + 구간마다 { 출발 시각 · 도착 시각 · 이동 시간 · 이동 수단 }
        또는  도착 불가 경고 { 어느 일정 · 몇 분 모자람 }
```

**규칙**
- 총 이동 시간을 가장 짧게 하는 순서를 고른다 (FR-2.2)
- 시간 고정형 일정의 앞뒤 순서와 시각은 바꾸지 않는다. 유연형만 자리를 옮긴다 (FR-2.3)
- 사용자가 손으로 고정한 자리는 바꾸지 않는다 (FR-2.6, S-10)
- 어떤 순서로도 고정형 일정에 제때 닿을 수 없으면 순서를 주지 않고 경고를 준다 (FR-2.5, NFR-2.1)
- 시각은 사용자의 표준시로 다루고 자정을 넘겨도 어긋나지 않는다 (NFR-2.3)
- 일정이 없거나 하나뿐이어도 오류 없이 끝난다 (NFR-3.2)

**왜 이동 시간을 받아오나** — 외부를 직접 부르지 않으므로, 이동 시간을 대역으로 넣으면 외부 없이 테스트된다 (NFR-3.1, Q5-A).

### C-3 중간지점 계산

**책임** — 참여자들의 출발지에서 이동 시간 편차가 작아지는 지점을 찾는다.

```
받는 것 :  참여자들 { 이름 · 출발지 좌표 · 이동 수단 }
        +  출발지→후보지점 이동 시간을 물어볼 수단 (C-7 이 넘겨받아 쓴다)

주는 것 :  중간지점 좌표 + 참여자별 예상 이동 시간
```

**규칙**
- 참여자별 이동 시간의 편차가 작아지는 지점을 고른다 (FR-3.3)
- 참여자마다 정한 이동 수단을 반영한다 (FR-3.5)
- 참여자가 한 명이어도 오류 없이 끝난다 (NFR-3.2)
- 고른 지점의 편차는 임의로 고른 다른 지점보다 작아야 한다 (NFR-2.4)

### C-4 출발시각 계산과 알림 예약

**책임** — 언제 나가야 하는지 정하고, 그 시각에 알림이 오도록 걸어둔다.

```
받는 것 :  동선 계산 결과 (구간별 도착 시각 · 이동 시간)
        +  여유 시간 (C-6)
        +  지금 시각 (밖에서 주입한다)

주는 것 :  일정마다 { 출발 시각 · 알림 시각 }
        +  걸어둔 알림
```

**규칙**
- `출발 시각 = 도착 시각 − 이동 시간 − 여유 시간` (FR-5.1, NFR-2.2)
- 앱 탭이 닫혀 있어도 알림이 온다. 브라우저를 완전히 종료하면 오지 않아도 된다 (FR-5.2, Q4-A)
- 알림에 어느 일정 · 어느 목적지인지 담는다 (FR-5.4)
- 일정 · 경로 · 이동 수단이 바뀌면 걸어둔 알림을 다시 잡는다 (FR-5.6)
- 이동 시간이 늘어 출발 시각이 앞당겨지면 다시 잡는다 (FR-6.2)
- 완료 표시된 일정의 알림은 걷어낸다 (S-5)
- 권한이 없으면 그 사실을 화면(V-8)에 알린다 (FR-5.5)

**지금 시각을 주입받는 이유** — 실제 시간을 기다리지 않고 검증하기 위해서다 (NFR-3.3).

### C-5 일정 보관소

**책임** — 브라우저에 남기고 다시 꺼낸다. Q4-C 에 따라 세 가지를 **따로** 둔다.

```
보관하는 것
  ① 개별 일정      직접 넣은 일정. 날짜를 하나 들고 있다
  ② 반복 규칙      { 무슨 요일 · 몇 시 · 일정 내용 }. 미래 날짜를 미리 만들지 않는다
  ③ 예외 기록      { 날짜 · 어느 반복 규칙 · 건너뜀 | 고쳐진 내용 }
  ④ 하루 설정      출발지 · 마지막 도착지
  ⑤ 참여자         약속에 딸린 참여자와 출발지
```

**규칙**
- 브라우저를 닫고 다시 열어도 남아 있다 (FR-7.1)
- 로그인을 요구하지 않는다 (FR-7.2)
- 전체 삭제로 ①~⑤ 를 모두 지운다. 되돌릴 수 없음을 미리 알린다 (NFR-4.4)
- 참여자의 주소 · 좌표는 브라우저와 창구 호출 밖으로 나가지 않는다 (NFR-4.2)

**왜 미래 날짜를 미리 만들지 않나** — 반복을 미리 펼쳐 두면 어디까지 만들지 정해야 하고 그 기간이 끝나면 또 채워야 한다. 규칙만 두고 볼 때 펼치는 편(C-1)이 FR-1.9 의 "그날만 고치기 · 건너뛰기"도 자연스럽게 담는다.

### C-6 설정

**책임** — 수치를 한곳에 모은다. 계산 요소에 숫자를 박지 않기 위한 자리다 (NFR-5.2).

| 값 | 쓰이는 곳 |
|---|---|
| 여유 시간 기본값 | C-4 출발시각 계산 (FR-5.3) |
| 기본 이동 수단 | C-1 · C-2 (S-3, 수단을 고르지 않은 일정) |
| 이동 시간 캐시 유지 시간 | C-7 (NFR-1.3) |
| 장소 검색 반경 | C-8 (S-13) |
| 중간지점 후보를 몇 개까지 볼지 | C-3 |

**규칙** — 이 값들은 설정에 살고, 계산 코드는 받아 쓴다. 사용자가 바꾸는 값(여유 시간 · 기본 이동 수단)과 앱이 정하는 값(캐시 유지 시간 · 반경)을 구분해 둔다.

### C-7 지도 창구 (Q3-C)

**책임** — 주소↔좌표 바꾸기와 길찾기(이동 시간). 외부와 닿는 두 군데 중 하나다.

```
받는 것 :  주소 글자  →  주는 것 :  좌표
받는 것 :  출발 좌표 · 도착 좌표 · 이동 수단  →  주는 것 :  이동 시간 (+ 최신 여부)
```

**규칙**
- 실시간 교통 상황이 반영된 이동 시간을 준다 (FR-6.1)
- 같은 구간 · 같은 수단은 정해진 유지 시간(C-6) 안에서 저장해 둔 값을 주고 외부를 부르지 않는다 (NFR-1.3)
- 외부가 응답하지 않으면 마지막으로 받아 둔 값을 주고, **최신이 아니라는 표시를 함께** 준다 (FR-6.3)
- 접근에 쓰는 비밀값은 소스에 넣지 않고 실행 환경에서 받는다 (NFR-4.1)
- 이 창구를 대역으로 갈아끼우면 C-2 · C-3 가 외부 없이 검증된다 (NFR-3.1)

### C-8 장소 창구 (Q3-C)

**책임** — 좌표 주변의 실제 장소를 찾는다. 외부와 닿는 나머지 하나다.

```
받는 것 :  중심 좌표 · 반경(C-6) · 카테고리
주는 것 :  장소 목록 { 이름 · 카테고리 · 좌표 · 중심에서의 거리 }
```

**규칙**
- 실제 장소 검색 서비스의 데이터를 쓴다 (FR-4.2)
- 반경 안에 하나도 없으면 없다고 알린다. 반경을 넓혀 다시 부를 수 있다 (S-13)
- 비밀값 취급은 C-7 과 같다 (NFR-4.1)

**왜 C-7 과 나눴나** — Q3-C. 주소 변환과 길찾기는 보통 한 지도 서비스가 함께 제공하니 묶고, 장소 검색은 다른 서비스로 바꿀 여지가 있어 떼어 둔다.

## 무엇이 오가나 — 두 가지 흐름

### 흐름 1 · 동선을 받는다 (S-8)

```
V-1 하루 보기
  └─ "오늘 동선 보여줘"
       C-1 일정 펼치기 ── C-5 보관소에서 ①②③④ 를 받아 그날 목록을 만든다
            │
            ▼
       C-2 동선 계산 ── 구간마다 C-7 에 이동 시간을 묻는다
            │            (C-2 는 C-7 을 직접 부르지 않고, 필요한 이동 시간을 받아 쓴다)
            ▼
       C-4 출발시각 계산 · 알림 예약 ── C-6 에서 여유 시간을 받는다
            │
            ▼
       V-3 동선 결과 표시 / V-8 알림 상태
```

### 흐름 2 · 약속 장소를 정한다 (S-11~S-14)

```
V-4 약속 패널
  └─ 참여자 · 출발지 입력  →  C-5 보관소 ⑤
       C-3 중간지점 계산 ── C-7 로 참여자별 이동 시간을 잰다
            │
            ▼
       V-5 중간지점 결과
            │  "이 근처 카페 보여줘"
            ▼
       C-8 장소 창구 ── C-6 의 반경을 쓴다
            │
            ▼
       V-6 장소 후보  →  하나 고르면 일정의 장소가 확정된다 (C-5)
            │
            ▼
       흐름 1 을 다시 돌린다 (동선 · 출발시각 다시 계산)
```
