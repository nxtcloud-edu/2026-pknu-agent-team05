# STEP 07 작업 단위 쪼개기 — 계획

> 산출물: `aidlc-docs/inception/application-design/unit-of-work.md`
> 근거: `execution-plan.md` (단위 ①~④ · Q1-C · Q5-C) · `components.md` (C-1~C-8 · V-1~V-9) · `stories.md` (S-1~S-16)

## 이 단계를 왜 돌리나

조건 단계지만 실행한다. `execution-plan.md` 에서 돌리기로 판정했다.
쪼갤 개수(네 덩어리)와 순서는 이미 정해져 있다. 여기서 하는 일은 **경계를 못 박는 것**이다.

이미 정해진 것 — 손대지 않는다:

| 순서 | 단위 | 구성 요소 | 화면 | 스토리 |
|---|---|---|---|---|
| ① | 일정 관리와 저장 | C-1, C-5, C-6 | V-1, V-2, V-7, V-9 | S-1~S-6, S-16 |
| ② | 동선과 이동시간 | C-2, C-7 | V-3 | S-7~S-10 |
| ③ | 출발 알림 | C-4 | V-8 | S-15 |
| ④ | 약속 · 중간지점 · 장소 | C-3, C-8 | V-4, V-5, V-6 | S-11~S-14 |

③ 을 끝낸 시점이 "돌아가는 앱"의 기준이다 (Q5-C).

## 무엇을 할지

- [x] 단위 이름을 확정한다 (Q1 답에 따른다). 이 이름이 `construction/{단위이름}/` 폴더 이름이 된다 — `schedule-core` · `route-planning` · `departure-alarm` · `meetup-midpoint` (Q1-A)
- [x] 단위마다 **무엇이 들어오고 무엇이 나가는지** 적는다 — 특히 ② 의 동선 결과를 ③ 이 어떻게 받는지 — 경계 1~4 로 못 박음 (Q2-A)
- [x] 단위마다 **완료 기준**을 적는다 (Q3 답에 따른다) — 계산 단위 테스트 통과 (Q3-B). 화면·성능·실제 알림은 CONSTRUCTION 06 으로
- [x] 단위 사이 의존을 그린다 — 어느 단위가 없으면 어느 단위가 못 서는지
- [x] 단위마다 CONSTRUCTION 에서 돌 단계를 적는다 (01 · 02 · 05, 03·04 는 건너뜀) — 단위별 STEP 02 에서 고를 것까지 표로
- [x] 앞 단위를 뒤 단위가 고쳐야 할 때 어떻게 할지 정한다 (Q4 답에 따른다) — 그 자리에서 고치는 경우 3가지 · 되돌아가는 경우 3가지를 표로 (Q4-C)
- [x] 스토리 S-1~S-16 이 단위 하나에만 담기는지 확인한다 (두 단위에 걸친 스토리가 없어야 한다) — 16개 전부 하나. S-5 · S-11 · S-14 는 경계면을 통해서만 다른 단위를 건드린다

## 무엇을 하지 않나

- 단위 개수와 순서를 다시 정하지 않는다 — `execution-plan.md` 에서 확정했다
- **언어 · 프레임워크 · 외부 서비스를 고르지 않는다** — CONSTRUCTION STEP 02
- 함수 · 파일 · 데이터 타입을 정하지 않는다 — CONSTRUCTION 01
- 코드를 만들지 않는다
