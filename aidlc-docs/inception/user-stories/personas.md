# 페르소나

> 근거: `aidlc-docs/inception/requirements/requirements.md` · `story-generation-plan.md` Q1-A
> 페르소나는 **한 명**이다. 앱을 직접 쓰는 본인만 세운다.
> 약속 참여자는 앱을 쓰지 않는다 — 본인이 대신 출발지를 입력하는 **데이터**로 다룬다 (FR-3.1, Q2-A).

## P-1. 하루에 여러 곳을 돌아야 하는 본인 (유일한 사용자)

| 항목 | 내용 |
|---|---|
| 누구인가 | 앱을 자기 브라우저에 열어 혼자 쓰는 사람. 로그인하지 않는다 (FR-7.2) |
| 목표 | 하루에 흩어져 있는 볼일과 약속을 순서대로 돌면서, 총 이동 시간을 줄이고 어느 약속에도 늦지 않는 것 |
| 어떤 상황에서 쓰나 | 외출 전날 밤이나 그날 아침에 갈 곳을 몰아서 등록한다. 외출 중에는 화면을 계속 보지 않고, 출발할 때가 되면 알림으로 알아채고 싶다 (FR-5.2) |
| 겪는 불편 | 지도 앱을 여러 번 열어 구간마다 따로 검색해야 한다 · 순서를 어떻게 잡아야 덜 돌아다니는지 감으로 정한다 · 약속 장소를 정할 때 서로 얼마나 걸리는지 몰라 대충 중간쯤으로 잡는다 · 언제 나가야 하는지 매번 역산한다 |
| 무엇을 알고 있나 | 갈 곳의 이름이나 주소, 약속 시각, 참여자들이 어디서 출발하는지 |
| 무엇을 모르나 | 구간별 실제 이동 시간, 어떤 순서가 가장 짧은지, 참여자 모두에게 공평한 지점이 어디인지, 그 근처에 갈 만한 카페 · 식당이 있는지 |
| 기기 · 환경 | 브라우저 하나. 데이터는 그 브라우저에만 남는다 (FR-7.1). 앱 탭을 닫아 둔 채로도 알림을 받아야 한다 (FR-5.2) |
| 성공이란 | 일정을 넣어 두면 나가야 할 때 알림이 오고, 그 순서대로 다녔을 때 늦지 않는 것 |

### 이 페르소나가 만들어내는 제약

- 혼자 쓰므로 권한 · 공유 · 협업 화면이 없다 (Out of Scope)
- 참여자는 입력 대상이므로, 참여자용 화면이나 링크가 없다 (Out of Scope)
- 화면을 안 보는 시간이 길다 — 알림이 기능의 핵심이지 부가 기능이 아니다 (FR-5)
- 기기 하나에 데이터가 묶이므로, 지우면 복구할 방법이 없다. 삭제는 되돌릴 수 없다는 것을 화면에서 알려야 한다 (NFR-4.4)
